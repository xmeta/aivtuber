= AI VTuber
:toc:
:toclevels: 2

AI VTuber runtime focused on low latency, efficient reuse, and graceful degradation.

The core design separates three time scales:

* *Motor layer*: deterministic animation/audio scheduling.
* *Reflex layer*: fast structured decisions (Jev or compatible decision engine).
* *Thinking layer*: expensive generative reasoning only when necessary.

== Design goals

* Reuse pre-generated speech, lip-sync, expressions, gestures, and timing as versioned *Performance Assets*.
* Route common events through deterministic rules or Jev before invoking a large language model.
* Keep avatar, TTS, LLM, stream platform, and decision-engine integrations behind adapters.
* Preserve responsiveness when external AI services are slow or unavailable.
* Measure latency, cache hit rate, LLM call rate, cost, interruption quality, and reaction appropriateness.

== Rust workspace

The repository also pins a Rust 1.98.1 workspace under `crates/` for the deterministic core. Run the Rust checks locally:

[source,shell]
----
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo build --locked --workspace
cargo run --locked -p aivtuber-app --bin replay-benchmark -- examples/benchmarks/replay-comparison.json target/aivtuber-benchmarks
cargo run --locked -p aivtuber-hardening --bin failure-soak -- target/hardening-soak.json 5000
----

The Rust production path includes `crates/runtime` for security enforcement: byte-aware content ingress limits/backpressure, authenticated emergency-control bypass, memory-write gating, public-output gating, and redacted audit records. The default stdin composition also bounds raw records and its pre-runtime channel before `SecurityRuntime`; oversized/queue-full raw input is dropped with structured counters rather than accumulated in memory. `crates/adaptation` adds bounded working memory, pseudonymous viewer/topic relevance, deterministic generated-asset promotion/invalidation, and replayable adaptation decisions; durable memory still requires the non-serializable permit minted by `SecurityRuntime`. `crates/hardening` provides test/tooling-only deterministic fault injection and long-stream logical-time soak reports. Privileged OBS/avatar/tool actions require the non-serializable `AuthenticatedControl` authority minted by `LocalControlIngress`; serialized `AuthorizationContext` values are audit/replay data only. `crates/domain` defines bounded/versioned `ReflexRequest` snapshots and a separate curated `ThinkingRequest` carrying explicit trust/privacy metadata rather than arbitrary state maps or raw history. `crates/app` is the executable composition root: it owns lifecycle, content ingress, cached/reflex-selected/generated asset playback, adaptation APIs, the shared deterministic scheduler, and dispatch to real audio/VTube Studio/OBS adapter boundaries.

== Implementation roles

The repository currently keeps two implementations for different purposes:

* *Rust under `crates/` is the production-target deterministic core.* Roadmap/P0 acceptance criteria for domain, scheduling, assets, replay, and reflex execution are not considered complete until the required behavior exists and is tested on the Rust path, unless an issue explicitly says otherwise.
* *TypeScript under `src/` is an executable reference/prototype and regression harness.* It is useful for contract exploration, security fixtures, mocks, and cross-runtime parity tests, but a TypeScript-only implementation does not by itself close a Rust production-core acceptance criterion.

Cross-runtime behavior that is intentionally shared (for example seeded variation) should be pinned by parity tests or common fixtures.

== Runtime bootstrap (TypeScript)

A minimal deterministic security core lives under `src/`:

* `src/envelope.ts` -- provider-neutral event normalization with strict kind bindings and trust-boundary enforcement (threat model sections 3-5).
* `src/security.ts` -- deterministic capability authorization and memory-write gating.
* `src/rate-limit.ts` -- per-source token-bucket rate limiting with a separate bounded control-plane queue.
* `src/regression.ts` -- loads the fixtures from `examples/security/` and asserts the expected outcomes (threat model section 14).

The first slice of the deterministic performer (historical implementation Phase 1) is also implemented:

* `src/rng.ts` -- seeded mulberry32 PRNG with bounded variation (architecture section 8).
* `src/asset-store.ts` -- in-memory Performance Asset store with variant groups and compatibility lookups.
* `src/scheduler.ts` -- priority classes, cooldowns, minimum reaction spacing, and deterministic interruption arbitration.
* `src/performer.ts` -- event trace to performance plan. The replay exit criterion is enforced by tests: the same trace, assets, and seed reproduce the identical plan; a different seed changes variation but not structure.
* `src/event-bus.ts` -- bounded prioritized event bus; control plane drains first and content overflow drops the lowest priority (threat model section 9).
* `src/adapters.ts` -- mock audio/avatar adapters producing recorded deterministic outputs, with independent degradation.
* `src/session.ts` -- end-to-end session runner (bus -> performer -> adapters) with a replay fingerprint: identical inputs produce identical recordings.
* `src/reflex.ts` -- provider-neutral TypeScript reference `DecisionEngine` contract and `ReflexDirector`: strict deadline with timeout-as-control-flow, deterministic interrupt/route policy in code, low-confidence and cache-reuse thresholds, and a normalized deterministic fallback (domain contract sections 5-7, jev-routing sections 4-6). Provider wire types stay outside the domain contract.
* `src/adapters-jev.ts` -- legacy TypeScript Jev prototype/reference implementation. It is retained for prototype regressions, but the production-target System One wire contract now lives in Rust under `crates/reflex`; do not use the TypeScript wire DTOs as the authoritative API shape.
* `src/output-gate.ts` -- deterministic output gate (threat model section 11): allow / redact secret-shaped tokens / replace with a cached reaction / suppress control-plane text; hook failures fail closed.
* `src/thinking.ts` -- provider-neutral `ThinkingEngine` LLM contract (historical implementation Phase 4): curated request context (never raw history), structured-output expectations, ordered streaming chunks with a final finish reason, typed failure reasons, and LLM output kept strictly as data with no capabilities (threat model section 2).
* `src/tts.ts` -- provider-neutral `TtsEngine` contract (historical implementation Phase 4): single-shot and streaming audio synthesis with ordered chunks, aligned viseme timelines, typed failure reasons, and version identity for cache keys (architecture section 7).
* `src/adapters-mocks.ts` -- deterministic mock implementations of both contracts: scriptable streaming/failure scenarios proving the generic interface and every failure path without external services.

Run the unit and regression suites with:

[source,text]
----
bun test
----

== Status

Current delivery work is organized by the Stage 1-5 GitHub milestones documented in link:docs/roadmap.adoc[Roadmap]. Stage 1 converges on the https://github.com/xmeta/aivtuber/issues/97[v0.1 minimum usable live-stream release gate]; GitHub issue milestone/priority/status metadata is the live source for implementation ordering.

Delivery Stage 1 (Production Runtime Foundation). CI and the Rust workspace are operational. The Rust provider-neutral domain and deterministic scheduler/replay core include explicit lifecycle state, safe-point/phrase-boundary preemption, blend/exclusivity arbitration, seeded variation, causal replay ordering, and deterministic mock sinks. `crates/reflex` now adds deterministic semantic Top-K retrieval, the current TypeSafe System One/Jev wire adapter, absolute-deadline retry/fallback handling, explicit candidate reuse gating, and separate evidence/policy/execution replay stages. The TypeScript reference harness remains useful for security fixtures and LLM/TTS mock contracts.

The Rust production core includes the executable Performance Asset subsystem in `crates/asset-store`, cached filler/reaction playback in `crates/runtime`, real VTube Studio/OBS/audio/Thinking/TTS adapters in `crates/adapters`, and the executable `aivtuber-app` composition root in `crates/app`. The cached/reflex path traverses normalized content ingress -> compatibility-filtered AssetStore embedding snapshot -> deterministic semantic Top-K/Jev reuse gate -> retrieval-time asset identity check -> deterministic Scheduler -> audio/avatar output. The #9 production generative path now maps `ExecutedAction::Llm` to an explicit typed generation route, builds a bounded curated `ThinkingRequest`, gates generated text with `SecurityRuntime::publish_text` before TTS, inserts only complete validated generated assets into the hot AssetStore, and then reuses the same `CachedPerformer` / Scheduler timeline. Higher-priority and authenticated emergency cancellation use the scheduler's shared event-priority mapping; partial streaming output never becomes scheduler/reusable state. Adapter failures degrade independently, failed/due commands are not replayed after reconnect, and serialized control claims remain unable to cross the authenticated capability boundary.
