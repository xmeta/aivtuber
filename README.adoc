= AI VTuber
:toc:
:toclevels: 2

AI VTuber runtime focused on low latency, efficient reuse, and graceful degradation.

The core design separates three time scales:

* *Motor layer*: deterministic animation/audio scheduling.
* *Reflex layer*: fast structured decisions (Jev or compatible decision engine).
* *Thinking layer*: expensive generative reasoning only when necessary.

== Design goals

* Reuse pre-generated speech, lip-sync, expressions, gestures, and timing as versioned *Performance Assets*.
* Route common events through deterministic rules or Jev before invoking a large language model.
* Keep avatar, TTS, LLM, stream platform, and decision-engine integrations behind adapters.
* Preserve responsiveness when external AI services are slow or unavailable.
* Measure latency, cache hit rate, LLM call rate, cost, interruption quality, and reaction appropriateness.

== Validation

Every example and regression fixture is validated against its schema by:

[source,text]
----
bun install
bun run validate
----

The harness also asserts that fixtures under `examples/events/invalid/` are rejected by the Event Envelope schema.
CI runs this check on every push and pull request.

== Runtime bootstrap (TypeScript)

A minimal deterministic security core lives under `src/`:

* `src/envelope.ts` -- provider-neutral event normalization with strict kind bindings and trust-boundary enforcement (threat model sections 3-5).
* `src/security.ts` -- deterministic capability authorization and memory-write gating.
* `src/rate-limit.ts` -- per-source token-bucket rate limiting with a separate bounded control-plane queue.
* `src/regression.ts` -- loads the fixtures from `examples/security/` and asserts the expected outcomes (threat model section 14).

The first slice of the deterministic performer (roadmap phase 1) is also implemented:

* `src/rng.ts` -- seeded mulberry32 PRNG with bounded variation (architecture section 8).
* `src/asset-store.ts` -- in-memory Performance Asset store with variant groups and compatibility lookups.
* `src/scheduler.ts` -- priority classes, cooldowns, minimum reaction spacing, and deterministic interruption arbitration.
* `src/performer.ts` -- event trace to performance plan. The replay exit criterion is enforced by tests: the same trace, assets, and seed reproduce the identical plan; a different seed changes variation but not structure.
* `src/event-bus.ts` -- bounded prioritized event bus; control plane drains first and content overflow drops the lowest priority (threat model section 9).
* `src/adapters.ts` -- mock audio/avatar adapters producing recorded deterministic outputs, with independent degradation.
* `src/session.ts` -- end-to-end session runner (bus -> performer -> adapters) with a replay fingerprint: identical inputs produce identical recordings.
* `src/reflex.ts` -- provider-neutral `DecisionEngine` contract and `ReflexDirector`: strict deadline with timeout-as-control-flow, deterministic interrupt/route policy in code, low-confidence and cache-reuse thresholds, and a normalized deterministic fallback (domain contract sections 5-7, jev-routing sections 4-6). Jev wire types stay inside future adapters.
* `src/adapters-jev.ts` -- Jev HTTP adapter implementing `DecisionEngine`: wire DTOs sealed inside the adapter, HTTP failure modes mapped to typed fallback reasons, deadline aborts surfaced as `timeout`, secrets referenced by identifier only.
* `src/output-gate.ts` -- deterministic output gate (threat model section 11): allow / redact secret-shaped tokens / replace with a cached reaction / suppress control-plane text; hook failures fail closed.

Run the unit and regression suites with:

[source,text]
----
bun test
----

== Status

Bootstrap phase. Schema/fixture validation, CI, the deterministic security core, and roadmap phase 1 (event bus, seeded variation, asset store, scheduler, deterministic performer, mock adapters, session replay recording) are implemented; next targets are viseme/gesture timeline playback in the mock adapters, the reflex routing adapter, and VTube Studio/OBS integration planning.
