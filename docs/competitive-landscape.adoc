= Competitive Capability Landscape
:toc:
:toclevels: 2

*As of: 2026-11-09* (repository `main` at `8e6252ca`; competitor facts fetched the same day).

This document compares aivtuber with the strongest open-source rivals and with two voice-agent frameworks used as references.
It is a maintained *evidence table*, not a roadmap and not marketing.
GitHub issues remain the source of truth for ownership and readiness (link:roadmap.adoc[Roadmap]); external patterns are mapped to issues in link:research-register.adoc[Research and Design Register]; dependency decisions live in link:reuse-first.adoc[Reuse-First matrix] and link:supply-chain.adoc[Supply chain].

== 1. Reading rules

Every aivtuber cell uses exactly one status word, and a claim without that word is a defect in this document.

[cols="1,4"]
|===
|Status |Meaning

|*shipped*
|Code on `main` exists and is cited as `path:line`. It says nothing about quality or about a live-stream run unless a run record is cited.

|*designed (ADR-000N)*
|Only a Proposed ADR exists. No production code. An ADR spike or throwaway script is not shipped code.

|*measured (EXP-0001)*
|An offline experiment produced numbers. The experiment code is throwaway; nothing is in `crates/`.

|*not started*
|No code, no ADR. An issue number is given when one exists.
|===

Competitor cells state what the cited README or source says and nothing else.
A competitor cell that says "not seen" means the stated files were searched and nothing was found; it is not a claim of absence.
No competitor was run, so latency, quality, reliability and barge-in behaviour are *not compared* anywhere in this document.

== 4. Where we lead (verified only)

Each item below is a design property that was checked in code or a recorded run; none is a statement about overall product quality.

. *Authority is data-type enforced, not prompt enforced.* Memory writes require a non-serializable permit that only the security runtime constructs (`crates/runtime/src/lib.rs:221`), and privileged control requires a non-serializable proof minted only by authenticated local ingress (`crates/domain/src/control.rs:46`). No competitor README or the pipecat / livekit READMEs describe an equivalent; this is an absence in READMEs, not an exhaustive source search.
. *Untrusted public chat cannot self-escalate.* The Twitch path pins chat to `untrusted` / `public_chat` and the app rejects anything above an operator ceiling (`crates/app/src/main.rs:102`); a test sends forged moderator and broadcaster badges and a forged command and checks no capability results (`crates/app/tests/twitch_ingress_e2e.rs:52`).
. *Emergency stop is independent of the content path and has been exercised live with real adapters.* Operator `stop` and `mute` went through during non-idle activity in a 34 minute run with real VTube Studio and OBS, including adapter degradation that did not freeze the performer (`docs/release-v0.1.adoc` section 12).
. *Replay and failure evidence is part of the repository.* Deterministic scheduler replay, a benchmark gate, soak and fuzz targets exist in-tree. The only comparable item seen elsewhere is livekit's built-in test framework (README 42), which tests agent behaviour rather than replaying scheduler decisions.
. *Japanese turn-observation numbers exist and were published with their limits.* EXP-0001 measured VAD cost and compared Smart Turn v3.2 with fixed-silence rules on Japanese read speech; it found Smart Turn did not beat the fixed-800 ms rule on false turn-take rate. This is a lead in evidence, not in shipped capability (nothing of it is in `crates/`), and the labels were constructed (see the EXP-0001 limitations).

== 8. Limits of this document

* No competitor was run. Nothing here compares latency, quality, stability or barge-in behaviour.
* README feature lists are marketing text. A checked box (AIRI) or a bullet (OLV) means the maintainers claim it, not that it works well.
* "Not seen" for a competitor means the cited README and listings only; the source trees were not exhaustively searched.
* For this project, `shipped` rows were checked by reading the cited lines on `main`; whether each path is exercised by a default CI gate or a live run is stated only where a record is cited.
* Search for this project was done with tgrep 1.0.11 against an index built from this checkout.

== 9. How to refresh

. Create a branch from current `origin/main`, update the *As of* date and commit id at the top.
. Re-run `gh repo view <owner/repo> --json stargazerCount,pushedAt,licenseInfo,isArchived` for every repository in sections 2 and 6, and update the figures.
. Re-fetch the READMEs (`gh api repos/<owner/repo>/readme -H "Accept: application/vnd.github.raw"`) and re-check every cited line number; line numbers drift with every README edit.
. For each aivtuber `shipped` row, run `tgrep -n '<symbol>' .` and confirm the cited `path:line`. Move a row to `shipped` only with a code citation; never from an ADR or issue.
. Re-read the live labels with `gh issue list --state open --json number,title,labels` and update section 5; reorder by user-visible impact, not by label.
. Run `bun scripts/validate.mjs`.

Refresh at least when a competitor ships a release that changes a matrix cell, when an ADR in this table changes status, or before a public comparison is made from this document.
