== 1. Reading rules

Every aivtuber cell uses exactly one status word, and a claim without that word is a defect in this document.

[cols="1,4"]
|===
|Status |Meaning

|*shipped*
|Code on `main` exists and is cited as `path:line` (lines are from `main` at the as-of commit and drift). It says nothing about quality or about a live-stream run unless a run record is cited.

|*designed (ADR-000N)*
|Only a Proposed ADR exists. No production code. An ADR spike or throwaway script is not shipped code.

|*measured (EXP-000N)*
|An offline experiment produced numbers. The experiment code is throwaway; nothing is in `crates/`.

|*not started*
|No code, no ADR. An issue number is given when one exists.
|===

Competitor cells state what the cited README, release or source says and nothing else.
A competitor cell that says "not seen" means the stated files were searched and nothing was found; it is not a claim of absence.
No competitor was run, so latency, quality, reliability and barge-in behaviour are *not compared* anywhere in this document.
"Unverified" marks a fact this edition could not confirm from a primary source.

== 4. Where we lead (verified only)

Each item below is a design property that was checked in code or a recorded run; none is a statement about overall product quality.

. *Authority is data-type enforced, not prompt enforced.* Memory writes require a non-serializable permit that only the security runtime constructs (`crates/runtime/src/lib.rs:236`), and privileged control requires a non-serializable proof minted only by authenticated local ingress (`crates/domain/src/control.rs:46`). No competitor README or the pipecat / livekit READMEs describe an equivalent; this is an absence in READMEs, not an exhaustive source search.
. *Untrusted input cannot self-escalate, including speech.* The Twitch path pins chat to `untrusted` / `public_chat` and the app rejects anything above an operator ceiling (`crates/app/src/main.rs:126`); a test sends forged moderator and broadcaster badges and a forged command and checks no capability results (`crates/app/tests/twitch_ingress_e2e.rs:52`). Transcripts from the microphone are assigned `speech` / `content` / `untrusted` by the runtime, never by the sidecar (`docs/production-runtime.adoc:138`).
. *Emergency stop is independent of the content path, reaches already-started audio, and has been exercised live with real adapters.* Operator `stop` and `mute` went through during non-idle activity in a 34 minute run with real VTube Studio and OBS, including adapter degradation that did not freeze the performer (`docs/release-v0.1.adoc` section 12). Ending audio that had already started was a defect (#277) fixed in #278 after that run; the live record predates the fix.
. *Replay and failure evidence is part of the repository, now including the voice path.* Deterministic scheduler replay, a benchmark gate, soak and fuzz targets exist in-tree, and the floor policy, barge-in stop and phrase commit order are replayed (`crates/scheduler/src/replay.rs`, tests `replay_records_the_phrase_commit_order_and_horizon`). The only comparable item seen elsewhere is livekit's built-in test framework (README 42), which tests agent behaviour rather than replaying scheduler decisions.
. *The zero-paid local run is measured, and its network claim was checked.* The `local` profile has a recorded end-to-end run with latency per stage, resources, a socket sample showing no non-loopback connection from the runtime's processes, and failure cases (`docs/local-profile-quickstart.adoc` section 10). OLV and my-neuro also claim offline operation (OLV README 67; my-neuro README 42, "under 1 second", unverified); no competitor was run, so this is a lead in published evidence, not in speed or reliability.
. *Japanese speech engines were benchmarked with their limits published.* EXP-0001 (turn observation), EXP-0002 (STT) and EXP-0003 (TTS) report intervals, sample sizes and constructed labels. This is a lead in evidence; the engines themselves are not a lead (VOICEVOX had the lower reading error in EXP-0003).

== 5. Where we trail

Impact means what a Japanese-speaking streamer or their viewers notice first when comparing with AIRI, OLV or AITuberKit. Status labels were read from GitHub on 2026-11-10. This section recommends an order; it files nothing. *Slice size* is a rough estimate (not measured): *S* is one reviewed PR, *M* two to four PRs, *L* five or more or needs an ADR and a spike first. The "Japanese streamer" weighting is an assumption stated here, not a measured audience: AITuberKit and aituber-onair are the Japanese-community projects and both support YouTube comments (README cites below).

== 8. Limits of this document

* No competitor was run. Nothing here compares latency, quality, stability or barge-in behaviour.
* README feature lists are marketing text. A checked box (AIRI) or a bullet (OLV) means the maintainers claim it, not that it works well.
* "Not seen" for a competitor means the cited README and listings only; the source trees were not exhaustively searched. Directory names in AIRI's `packages/` and `services/` were listed, not read.
* The new-project search (section 2) used a handful of keywords on GitHub only; projects hosted elsewhere or described in other languages may be missing. Star counts say nothing about Japanese adoption.
* The streamer-impact ranking in section 5 is a judgement from the cited evidence plus the stated assumption about YouTube; it was not derived from user research. Slice sizes are estimates.
* For this project, `shipped` rows were checked by reading the cited lines on `main` at `83497790`; whether each path is exercised by a default CI gate or a live run is stated only where a record is cited. Every end-to-end voice and local-profile measurement in this repository comes from one Windows host and a PCM file in place of a microphone.
* ADR-0003, ADR-0004, ADR-0005 and ADR-0006 still carry `:status: Proposed`; this document treats code on `main`, not ADR status, as the evidence for `shipped`.
* Search for this project was done with tgrep 1.0.11 against an index built from this checkout.

. Create a branch from current `origin/main`, update the *As of* date and commit id at the top.
. Re-run `gh repo view <owner/repo> --json stargazerCount,pushedAt,licenseInfo,isArchived` and `gh release list -R <owner/repo> -L 2` for every repository in sections 2 and 6, and update the figures.
. Re-fetch the READMEs (`gh api repos/<owner/repo>/readme -H "Accept: application/vnd.github.raw"`) and re-check every cited line number; line numbers drift with every README edit.
. Re-run the new-project search in section 2 and add anything prominent, with its licence.
. For each aivtuber `shipped` row, run `tgrep -n '<symbol>' .` and confirm the cited `path:line`. Move a row to `shipped` only with a code citation; never from an ADR or issue.
. Re-read the live labels with `gh issue list --state open --json number,title,labels` and update section 5; reorder by user-visible impact, not by label.
. Run `bun run validate`.

Refresh at least when a competitor ships a release that changes a matrix cell, when an ADR in this table changes status, or before a public comparison is made from this document.
