= VTube Studio and OBS Adapter Integration
:toc:

== 1. Scope

The Rust production adapters live in `crates/adapters`.

They implement the provider-neutral `AvatarAdapter` and `StreamAdapter` contracts from `aivtuber-domain` while keeping websocket wire details outside the domain layer.

The adapters are deliberately replaceable through injected `WebSocketConnector` / `WebSocketTransport` implementations. Unit tests use scripted transports; production uses Tungstenite.

== 2. VTube Studio

Official API documentation:

* https://github.com/DenchiSoft/VTubeStudio[VTube Studio Public API]
* https://github.com/DenchiSoft/VTubeStudio/blob/master/Events/README.md[VTube Studio Event API]

Default endpoint: `ws://127.0.0.1:8001`.

Supported production slice:

* token request and plugin authentication;
* configurable endpoint;
* hotkey execution through `HotkeyTriggerRequest`;
* parameter injection through `InjectParameterDataRequest`;
* event subscription through `EventSubscriptionRequest`;
* bounded reconnect/backoff;
* no queued action replay after reconnect.

The authentication token is held in `SecretString`, whose `Debug` output is redacted.

== 3. OBS websocket 5.x

Official protocol documentation:

* https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md[obs-websocket 5.x protocol]

Default endpoint: `ws://127.0.0.1:4455`.

The adapter implements the required 5.x handshake:

. receive `Hello` (op 0);
. derive the SHA-256/base64 authentication response when a challenge is present;
. send `Identify` (op 1), including configured event subscriptions;
. wait for `Identified` (op 2);
. issue requests using op 6 and validate op 7 responses.

Supported performer control actions:

[cols="1,1"]
|===
|Domain action |OBS 5.x request

|`scene.set`
|`SetCurrentProgramScene`

|`source.visibility.set`
|`SetSceneItemEnabled`

|`audio.mute.set`
|`SetInputMute`

|`audio.volume.set`
|`SetInputVolume`
|===

OBS passwords are held in `SecretString` and are redacted from `Debug` output.

== 4. Disconnect and reconnect behavior

Adapters do not own scheduler state.

A failed connection/request returns a typed `EngineErrorKind::Unavailable` to the adapter caller. It does not mutate or stop the deterministic scheduler.

Reconnect uses bounded exponential backoff. The adapter does not keep a pending action queue across disconnects, so reconnect cannot replay a stale avatar or OBS action. Only a newly submitted action after reconnection is sent.

VTube Studio event subscriptions are remembered as configuration and re-established after reconnect. OBS subscriptions are part of Identify/Reidentify state and are likewise restored without replaying control actions.

== 5. Local smoke tests

Live tests are ignored by default and never run in CI.

=== VTube Studio

Enable *Allow Plugin API access* in VTube Studio, then run:

[source,shell]
----
AIVTUBER_VTS_ENDPOINT=ws://127.0.0.1:8001 AIVTUBER_VTS_TOKEN='<existing-token-if-you-have-one>' cargo test -p aivtuber-adapters --test live_smoke vtube_studio_live_smoke -- --ignored --nocapture
----

If `AIVTUBER_VTS_TOKEN` is omitted, VTube Studio may show the normal plugin approval prompt and the acquired token is session-local.

To additionally test a disposable hotkey:

[source,shell]
----
AIVTUBER_VTS_HOTKEY='Wave' cargo test -p aivtuber-adapters --test live_smoke vtube_studio_live_smoke -- --ignored --nocapture
----

Use a harmless hotkey on a test model.

=== OBS

Enable obs-websocket 5.x in OBS and run:

[source,shell]
----
AIVTUBER_OBS_ENDPOINT=ws://127.0.0.1:4455 AIVTUBER_OBS_PASSWORD='<obs-websocket-password>' cargo test -p aivtuber-adapters --test live_smoke obs_live_smoke -- --ignored --nocapture
----

To additionally switch to a disposable test scene:

[source,shell]
----
AIVTUBER_OBS_SCENE='Adapter Smoke Test' cargo test -p aivtuber-adapters --test live_smoke obs_live_smoke -- --ignored --nocapture
----

Do not place real tokens/passwords in repository files, shell history shared with others, test output, or issue/PR text.

== 6. Local avatar renderer (`local-avatar/1`)

The local avatar output is the zero-paid-dependency alternative to VTube Studio (ADR-0003, issue #219). The Rust runtime hosts a loopback HTTP + WebSocket listener; the renderer page (OBS Browser Source, a webview or a local browser) is the WebSocket client. The renderer page lives in `renderer/local-avatar/` (TypeScript, Vite, three.js and `@pixiv/three-vrm`, exact-pinned, no CDN). The Rust host, the protocol and a mock-renderer test suite are covered by `cargo test`; the real page is covered by a headless end-to-end smoke test (see "CI and smoke test" below).

=== Selecting and running it

[source,sh]
----
export AIVTUBER_AVATAR_OUTPUT=local          # local | vts | none; unset keeps AIVTUBER_VTS_ENABLED behavior
export AIVTUBER_LOCAL_AVATAR_PORT=8765       # 127.0.0.1 only; there is no bind-address option
export AIVTUBER_LOCAL_AVATAR_PAGE_DIR=./renderer/local-avatar/dist   # built renderer bundle
export AIVTUBER_LOCAL_AVATAR_QUEUE=64        # outbound queue capacity
----

The queue-age limit reuses `AIVTUBER_MAX_DISPATCH_LATENESS_MS`. On start the runtime prints one line on stderr with the launch URL (`http://127.0.0.1:<port>/?token=...`); give exactly that URL to the OBS Browser Source. The URL contains the per-launch secret: do not paste it into issues, shared logs or screenshots, and do not capture the runtime's stderr into shared logs. The token is never written by the adapter itself and `Debug` output redacts it.

CI test (no GPU, no browser): `cargo test --locked -p aivtuber-adapters --test local_avatar`.

=== Building the renderer

The bundle is built by the operator; `dist/` is not committed and nothing is fetched from a CDN at runtime. You need Bun and Node.

[source,sh]
----
cd renderer/local-avatar
bun install --frozen-lockfile --ignore-scripts
bun run build                         # writes renderer/local-avatar/dist
cp /path/to/your-model.vrm dist/model.vrm   # operator-supplied model, see "Model and rights"
cd ../..
AIVTUBER_AVATAR_OUTPUT=local AIVTUBER_LOCAL_AVATAR_PAGE_DIR=./renderer/local-avatar/dist cargo run --locked -p aivtuber-app
----

The model must sit inside the served directory; the page loads the host's *active* model by default (`/avatar/model.vrm`, served only to a page that presents the per-launch token; without the avatar store that is the `model.vrm` in the served directory) and, every 2 seconds, asks `/avatar/active` for the active model's id so it reloads itself when the operator chose another in the panel (#362). To pin the page to another file in the same directory add `&model=other.vrm` to the launch URL (this also turns the reload off) (same-origin paths of `[A-Za-z0-9._/-]` only; anything else is refused by the page).

The page connects to the host with the token in its own URL, mints a fresh epoch for every connection, loads the model, renders one neutral frame and only then reports `ready`. It never connects without a rendered model, so a missing or broken model shows as `disconnected` health, with the reason in the page's browser console. On a socket drop it snaps to neutral and reconnects with a new epoch and a bounded backoff (250 ms doubling to 5 s).

=== OBS Browser Source capture (no paid software)

. Start the runtime as above and copy the `local avatar renderer URL` printed on stderr (`http://127.0.0.1:<port>/?token=...`). The token changes on every launch, so update the source URL after each restart.
. In OBS add a *Browser* source, paste that URL, and set *Width* and *Height* to your canvas, for example 1920 and 1080 (a portrait source such as 1080 by 1920 also works; the camera backs away to keep the avatar's shoulders in frame).
. Leave *Custom CSS* empty and keep *Shutdown source when not visible* off, otherwise the page disconnects and returns to neutral whenever the scene is hidden.
. The page background and canvas are transparent (`alpha` canvas, `clear alpha 0`), so the avatar composites over your scene without a chroma key. Do not add a background color in OBS.
. The page runs entirely in OBS's embedded browser (CEF/Chromium, WebGL2). It uses `requestAnimationFrame`, so its frame rate follows the Browser source's FPS setting.

OBS's own Browser Source was not run while writing this guide: the transparent output and rendering are verified in headless Chromium and system Edge (ADR-0003 assumption A-VRM-001 stays open until OBS is checked). Treat the first OBS run as part of the live smoke.

=== Model and rights

No VRM model is part of this repository. A VRM file carries its own license in its embedded metadata (`meta`: license URL, avatar permission, commercial usage, redistribution, credit notation, allowed modification) and that, not the code license of this project, governs what you may do with it. *You are responsible for checking that you have the right to use the model and to stream or publish it.* The page logs the model's `meta` summary and SHA-256 in the browser console when it loads (`[local-avatar] model loaded`) so you can read what you are about to broadcast; models are local files and are never uploaded to any service. Since issue #362 the operation panel does this reading for you: you pick the `.vrm` in the panel, the app inspects it, the panel shows the licence the file declares (VRM 1.0 `VRMC_vrm.meta` or VRM 0.x `VRM.meta`: name, authors, avatar permission, commercial usage, credit notation, modification, redistribution, licence URLs) with a clear warning when it limits the use, and the model becomes active only when you confirm; the avatar page then reloads it without a restart (see `docs/local-profile-quickstart.adoc`, "Choosing the avatar from the panel"). The file is untrusted data: the app checks the glTF binary structure before anything else reads it, and the meta text is shown as plain text. The checks are about the file's structure and what it says about itself, not about whether the statement is true; you remain responsible for the right to stream the model.

The tests and CI use `VRM1_Constraint_Twist_Sample.vrm` from `pixiv/three-vrm`, fetched pinned to commit `3caf7a21ee68f0d5dfa363ab3d577450bbf60136` and verified by SHA-256 `12c2b97e95e700783a6a550dc0eee2d7880aeedccef9ae67bc4c5a2f0f2631a2`. Its embedded VRM 1.0 metadata (read from the file) states: author and copyright `pixiv Inc.` (2022), license URL `https://vrm.dev/licenses/1.0/`, avatar permission `everyone`, commercial usage `corporation`, modification and redistribution allowed (`allowModificationRedistribution`), credit notation `unnecessary`, antisocial or hateful usage not allowed. No separate model license file was found in the upstream repository, so the file is downloaded for local testing only and is not copied into this repository.

=== CI and smoke test

The `renderer` job in `.github/workflows/ci.yml` runs typecheck, unit tests, the build, the license allowlist and `bun audit` (see `docs/supply-chain.adoc` section 8), then the headless smoke: `crates/app/examples/local_avatar_smoke.rs` starts the real `LocalAvatarOutput`, serving the built bundle plus the pinned sample model, and `renderer/local-avatar/smoke/smoke.mjs` opens its launch URL in headless Chromium forced to SwiftShader (`--use-angle=swiftshader --enable-unsafe-swiftshader`, no GPU). It asserts: `ready` arrives, every scripted command (reset, expression, gaze, visemes, reset) is acked by the host, the renderer's exposed expression values follow each command, a transparent screenshot has alpha 0 at all four corners and avatar pixels in the middle, no CSP violation occurs, and after a page reload a new epoch starts neutral with no old command replayed. Assertions are state-based: software GL renders at roughly 9 frames per second and spring-bone motion makes pixel comparison unreliable.

Run it locally (system Edge shown; omit `SMOKE_BROWSER_CHANNEL` to use Playwright's Chromium after `node node_modules/playwright-core/cli.js install chromium`):

[source,sh]
----
cd renderer/local-avatar && bun install --frozen-lockfile && bun run build && cd ../..
cargo build --locked -p aivtuber-app --example local_avatar_smoke
cd renderer/local-avatar
SMOKE_BROWSER_CHANNEL=msedge node smoke/smoke.mjs --bin ../../target/debug/examples/local_avatar_smoke
----

The read-only state hook `window.__avatarDebug.snapshot()` exists only when the page URL carries `debug=1`; it returns copies of epoch, last accepted seq, expression values and gaze, and accepts no input.

=== Security properties

* Binds `127.0.0.1` only. Remote exposure is not offered by this adapter.
* The token is 32 bytes from the OS CSPRNG, minted per launch, compared in constant time.
* The WebSocket upgrade requires the token, an `Origin` exactly equal to `http://127.0.0.1:<port>`, and a matching `Host` header (DNS-rebinding guard). Anything else gets HTTP 403, checked before the connection-limit check so an unauthenticated peer cannot probe for a live renderer.
* A second connection while one is live gets HTTP 409. The live connection is never displaced.
* Static files are served only from the configured directory, with a strict path allowlist, symlink-resolved containment, `GET`/`HEAD` only, `nosniff`, `no-store` and a CSP that restricts the page to its own origin (`blob:` is additionally allowed in `connect-src` because three.js decodes embedded model textures by fetching a `blob:` URL it created itself). The page is public to local processes by design and must hold no secret.
* Renderer frames are untrusted bounded data (4 KiB max, closed field sets, closed reject-reason set). They never feed authorization; each host command is still authorized with `Capability::AvatarControl` before it is queued.

=== Protocol

Adapter-private and versioned; it is deliberately not under `schemas/`. Fixtures: `crates/adapters/tests/fixtures/local-avatar-1/`.

----
host -> renderer:  {v, epoch, seq, cmd}   cmd.op = expression | gesture | gaze | viseme | reset
renderer -> host:  hello{v, epoch, model_hash, profile} | ready{epoch} | ack{epoch, seq} | reject{epoch, seq, reason}
----

The renderer mints `epoch`; the host mints `seq` (per epoch, starting at 1). `generation` and `at_ms` never go on the wire. `ready` is sent only after the first neutral frame of the epoch; the host sends nothing before it and then sends `reset` as `seq` 1.

=== Restart and failure semantics

* Commands queued for a previous connection or epoch are dropped and counted (`stale_epoch`), never replayed.
* A command older than the dispatch window when it could be sent is dropped (`expired`). The renderer has no TTL and no wall clock.
* The outbound queue is bounded (`queue_full` drops); with more than 64 unanswered commands the state is `degraded` and sending pauses.
* `LocalAvatarOutput::execute` never blocks and never returns an error for renderer weather; availability is reported through `connect()` into `AdapterHealth::avatar_error` and through `LocalAvatarHealth` counters (sent, acked, rejected by reason, dropped by reason, reconnects).
* A socket drop moves health to `disconnected`; the renderer snaps to neutral on its side.
