== Decision summary

* *Gate decision:* `NO-GO / incomplete`, unchanged. This is one run, not a calibrated SLO pass, and the host was not quiet (see <<Host conditions>>). The gate stays NO-GO until Track B (operator OBS + VRM + half-duplex mic + active stop/mute) and the #59 human quality review.
* *The topics difference is the headline.* `eval-a1` and `eval-a2` ran with `initiative_topics=0`; `a3` ran with `initiative_topics count=24` (the seeded starter list, read from `status` before the feed). `a3` is therefore not directly comparable to `a1`/`a2` on initiative metrics (voiced, repeat refusals, silent fallbacks, spacing, quiet windows, initiative repeat rate). Chat-path metrics are comparable only as far as host load was similar, which it was not.
* *Observed with topics:* `0` repeat refusals (`a2`: `7`), `0` silent fallbacks (`a1`/`a2`: `5`/`5`), every initiative voiced (`55` of `55`), no early re-fire needed, and the longest quiet-window silence fell to `60.7 / 61.7 / 62.3 s` (`a2`: `65.0 / 110.1 / 121.1 s`). This is consistent with the hypothesis. One run cannot establish it: the build and the host also differ from `a2`, and a no-topics run on the same build and host would be the controlling comparison.
* *Not improved:* direct first-phrase latency was again slow and noisy (p50 `2,611 ms` against `1,577 ms` in `a1`), on a host whose free RAM was lower than in `a2`. The crowd route fired once again (`n=1`).
* *Hard guardrails:* unchanged for what Track A can observe: no stop, no privilege escalation, `malformed=0`, `capped=false`, `truncated_read=false`, `0` provider failures, `0` generation fallbacks, clean exit. Operator stop/mute and visual sync remain not observed.

== Topics used

The `local-topics.txt` list holds `24` entries. The initiative rotates through the list one topic per fire with a recent-use skip, and `a3` fired `55` initiatives (more than `24`), each of which takes a topic. `24` of `24` distinct topics used is therefore derived from the code and the fire count, not read from the daemon: the `initiative_topics used=` counter was not sampled before the app exited on stdin EOF (a gap in this run; a future run should read `aivtuberctl status` shortly before the hour ends). The session log does not record which topic a turn used, and no transcript text is kept here.

== What this run does and does not show

* With a topic list the idle initiative produced no repeat refusals, no silent fallbacks, and a maximum silence of about `60-62 s` in each of the three quiet windows. This supports the #551 hypothesis that missing topics caused the monotony seen in `a1`/`a2`, but it is one run, it changes two things relative to `a2` (topics and build), and it does not measure how varied the speech sounds: topic variety and semantic repetition still need the #59 human review. The session log is retained outside Git for that review.
* The `a3` initiative did not need #545's early re-fire, so that path was not exercised.
* Chat-path latency did not improve. Direct and deferred latency stayed noisier than `a1` on a loaded host. The crowd route (`n=1`) was faster than in `a2`, which is not a finding at `n=1` with different host load.
* Chat exact repeats were `3` (rate `0.035`), the highest of the three runs; with `86` phrases this is not distinguishable from noise and is referred to the #59 review.
