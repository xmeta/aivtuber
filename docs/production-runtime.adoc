= Production Rust composition runtime

Issue #34 adds the first executable Rust composition root under +crates/app+.

The production path composes existing subsystems instead of duplicating them:

[source,text]
----
serialized EventEnvelope
        |
        v
SecurityRuntime content ingress
        |
        v
RoutePlanner
   | deterministic intent / cached asset
   | or ReflexPipeline -> explicit LLM route
        |                         |
        |                         v
        |                  GenerativePipeline
        |                  ThinkingEngine
        |                         |
        |                  SecurityRuntime::publish_text
        |                         |
        |                  TtsEngine -> complete PerformanceAsset
        |                         |
        |                  AssetStore::insert_hot
        |_________________________|
                  |
                  v
CachedPerformer
        |
        +--> compatibility-checked AssetStore
        +--> deterministic Scheduler
        |
        v
scheduled audio/avatar commands
        |
        +--> ProcessAudioPlayer
        +--> VtsAvatarOutput
----

OBS remains an independent control adapter. Its availability never owns scheduler state.

== Runtime invariants

* Raw stdin is byte-bounded and queue-bounded before +SecurityRuntime+; hostile line size or producer rate cannot create an unbounded pre-runtime buffer.
* Content bytes always pass through +SecurityRuntime::admit_content_bytes+.
* Operator/control events cannot enter the content ingress path.
* Cached playback uses the existing +CachedPerformer+ scheduler, not a second application scheduler.
* A production semantic index is built from the compatibility-checked `AssetStore` snapshot and precomputed versioned embeddings; index build/rebuild performs no scheduler/frame-path network I/O.
* A reflex-selected asset id is resolved by +AssetStore::resolve+ before playback. When retrieval supplied an asset identity, the current `AssetIdentity::stable_key()` must still match or playback is rejected as stale.
* Adapter commands are dispatched only while their scheduler generation is still live.
* Commands older than +AIVTUBER_MAX_DISPATCH_LATENESS_MS+ are dropped.
* Failed audio/avatar commands are not requeued. Reconnecting an adapter therefore cannot replay an already-due stale command.
* Authenticated emergency stop operates on the same scheduler used by cached/generated playback, purges pending commands, and cancels active generation independently of model/network availability.
* Generated public text always passes through +SecurityRuntime::publish_text+ before TTS. The current policy contains known control-plane command text and redacts configured secrets; it is not a general content-moderation classifier. Suppressed output never reaches TTS, and typed capability enforcement remains independent of text filtering.
* Every attempted LLM call is retained in the production audit with source event id, deterministic routing reason, and provider/model identity; prompt and generated reply text are excluded.
* Only complete, validated, runtime-compatible generated assets enter +AssetStore::insert_hot+; partial text/audio never reaches reusable asset or scheduler state.
* Generated assets are scheduled by the same +CachedPerformer+ / +Scheduler+ instance as cached assets, preserving one monotonic timeline for audio/visemes/avatar commands.
* Working memory is explicitly bounded by entry count, TTL, claim bytes, and topic bytes; raw viewer actor ids are replaced before storage with source-namespaced HMAC-SHA-256 pseudonyms under a deployment-only key.
* Durable memory writes require a non-serializable +MemoryWritePermit+ from +SecurityRuntime::authorize_memory_write+; public chat without that gate cannot become durable memory.
* Generated-asset promotion is explicit and deterministic: production records generated use, accepts quality labels separately, and only +apply_generated_asset_adaptation+ can promote or invalidate through the validated AssetStore path.
* Higher-priority generation cancellation uses the scheduler's shared +priority_for_event+ mapping.
* Serialized control events remain data only: content ingress rejects them and cannot use them to cancel/stop privileged runtime work.
* Operator control (issue #56) terminates in +LocalControlIngress+ on its own local-socket transport; the presented secret is verified in constant time before any +AuthenticatedControl+ is minted, every privileged action is capability-checked, and accepted/rejected actions are audited. The control endpoint never shares the untrusted content queue.
* VTube Studio and OBS connection failure is degraded state, not scheduler failure.

== Runtime retention

Long-running production state is governed by the shared +RuntimeRetentionPolicy+. Safe defaults, subsystem classification, logical-time eviction rules, observability, and the high-volume plateau verification are documented in +docs/runtime-retention.adoc+.

== Executable

Run the daemon from the repository root:

[source,shell]
----
export AIVTUBER_MEMORY_PSEUDONYM_KEY_HEX='<64 hex characters / 32 random bytes>'
# Optional non-secret rotation label; default is v1.
export AIVTUBER_MEMORY_PSEUDONYM_KEY_VERSION='v1'
cargo run -p aivtuber-app
----

The actor pseudonymization key is mandatory for the production composition root and is independent of the operator-control secret. Generate and store it as deployment secret material; do not place it in fixtures, replay metadata, logs, or model context. Rotating key/version intentionally breaks historical actor correlation unless records are explicitly migrated.

The process reads one Event Envelope JSON document per stdin line. Raw stdin is bounded before `SecurityRuntime`: the pre-runtime channel uses `sync_channel` with capacity equal to `SecurityRuntimeConfig::content_queue_limit`, and the line reader retains at most `max_envelope_bytes + 1` bytes while determining whether a record is oversized. An oversized record is drained through its newline and dropped; a record arriving while the raw queue is full is also dropped rather than blocking the reader. Both outcomes are exposed through `RawIngressMetricsSnapshot` and reported by the executable. Valid records retain input order.

Because the producer uses non-blocking `try_send`, a saturated raw queue cannot leave the stdin producer blocked on the application consumer during shutdown. The raw record-size limit is derived directly from `SecurityRuntimeConfig::max_envelope_bytes`, so the pre-runtime and runtime envelope limits cannot silently diverge. With the current default `SecurityRuntimeConfig`, this means a 64 KiB raw-record limit and a 1024-record pre-runtime queue.

The process advances the scheduler from a monotonic process clock and services due output commands on a short polling interval.

The starter pack contains descriptors and viseme metadata only. Audio binaries remain external to Git. Materialize the referenced files below the configured audio root before testing real playback.

== Ingress ceiling and Twitch chat (issue #257)

The stdin content ingress accepts what envelope validation accepts. A record declares its own `source_class`, `plane` and `trust_level`, and the runtime only checks that the declaration is self-consistent. `source` is chosen by the producer and is never evidence of where a record came from, so the operator, not the record, sets a ceiling on the ingress channel:

[cols="1,2,1"]
|===
|Variable |Meaning |Default

|`AIVTUBER_INGRESS_MAX_TRUST`
|Highest `trust_level` the pipe may declare: `untrusted`, `semi_trusted` or `trusted`.
|`trusted` (no change)

|`AIVTUBER_INGRESS_SOURCE_CLASSES`
|Comma-separated allow-set of `source_class` values, for example `public_chat`.
|all (no change)
|===

A record above the ceiling is rejected whole, audited as `rejected_ingress_policy`, and counted (`ContentAdmitDecision::RejectedIngressPolicy`; the total is printed when stdin closes). It is never rewritten or clamped, so a mislabelled producer is visible. An unrecognised value fails startup instead of silently widening the ceiling.

=== Twitch chat sidecar

`twitch-chat-ingress` (`crates/adapters`) is a separate read-only process. It uses the `twitch-irc` crate with the anonymous `justinfan` login: no OAuth, no credentials, and no send call exists in the binary. Provider types stay in `crates/adapters/src/twitch_chat.rs`; the output is the existing Event Envelope, one JSON line per chat message, so no wire contract is added.

[source,sh]
----
export AIVTUBER_INGRESS_MAX_TRUST=untrusted
export AIVTUBER_INGRESS_SOURCE_CLASSES=public_chat
cargo run --locked -p aivtuber-adapters --bin twitch-chat-ingress -- --channel somechannel \
  | cargo run --locked -p aivtuber-app
----

Options: `--channel` (repeatable, at most 8), `--queue N` (writer queue, default 256), `--stall-secs N` (rebuild the connection after this much silence, default 600), `--stats-secs N`, `--duration-secs N` (exit after N seconds). Diagnostics and counters go to stderr; stdout carries records only.

* *Trust.* Every record is `chat.message` / `public_chat` / `content` / `untrusted` with no `authorization`, whatever the message says. The ceiling above is what makes the app enforce that. Badges, emotes, channel and message id are carried in `payload` as audit data only; nothing reads a badge to decide anything, so a viewer claiming to be a moderator or broadcaster gains no capability and still cannot write memory.
* *Viewer identity.* `actor_id` is the numeric Twitch user id. Login and display name are not emitted. Pseudonymization happens in the app (`ActorPseudonymizer`, deployment key, applied when working memory is written); the sidecar never holds that key. Do not `tee` the pipe to a file you intend to keep: the raw numeric id is on the pipe.
* *Bounds.* Network messages go through a bounded writer queue; when it is full the newest record is dropped and counted (`dropped_queue_full`). Records or payloads over 64 KiB / 16 KiB are dropped and counted (`dropped_oversize`); the limits match `SecurityRuntimeConfig` defaults and a test pins them together. Reconnect uses capped exponential backoff, 1 s doubling to 60 s (`SIDECAR_RECONNECT`); `twitch-irc` also rate-limits new connections itself.
* *Deleted and cleared messages.* `CLEARMSG` and `CLEARCHAT` are counted (`messages_deleted`, `chats_cleared`) and not forwarded: the wire format has no retraction event, and a record already piped cannot be recalled.
* *TLS.* Connections use the platform TLS stack (`native-tls`: Schannel on Windows, OpenSSL on Linux).

Tests: `cargo test --locked -p aivtuber-adapters --lib twitch` (mapping fixtures, bursts, backoff) and `cargo test --locked -p aivtuber-app --test twitch_ingress_e2e` (stdin path, ceiling, forged message). A live run needs network access and is manual: `--duration-secs 120` against a busy public channel, piped into the app with the ceiling set.

== Speech observations (issue #92, S1)

`schemas/speech-observation.schema.json` is the contract for raw speech-activity edges and an optional turn-end score from a VAD or turn provider. It carries no audio, PCM or transcript text, and no source class, plane, trust or priority field: the receiving ingress assigns them. A microphone speaker, including the operator's own, is always `speech` / `content` / `untrusted` (`SpeechObservationProvenance`); it cannot mint authority, and priority comes from configuration.

Observations do not ride the stdin `EventEnvelope` pipe. An envelope kind would send them through the content queue and the scheduler's `Conversation` priority, and a signal is not content. They enter `SpeechObservationTracker::ingest_bytes` (size-bounded, schema-validated), which first applies the same operator ceiling as the stdin ingress (`IngressPolicy::admits_declared`): if `AIVTUBER_INGRESS_SOURCE_CLASSES` excludes `speech`, every batch is rejected and counted before parsing. The S2 sidecar uses a separate child-process pipe (see Speech sidecar below), never the stdin content pipe, and the same policy applies to it.

* *Stale rejection.* An activity edge older than `max_age_ms` (160), a turn-end score older than `turn_end_max_age_ms` (400), or any observation past its `expires_at_ms` is rejected and counted by reason (`stale_age`, `expired`, `future_dated`, `out_of_order`, `speaker_capacity`). Ordering uses observed time, never arrival, and nothing blocks.
* *Raw edges.* No debounce: a 32 ms fragment is an edge and restarts the silence clock (ADR-0005).
* *Bounded state.* At most 64 speakers; idle speakers are evicted after a logical-time TTL.
* *Fallback.* `fallback_turn_signal(state, now, config)` is a pure function that reports `turn_end_eligible` after 800 ms of silence. `SpeakerView` says why it applies (`no_turn_end_provider`, `unsupported_language`, `turn_end_stale`). Language is declared by configuration, never inferred. A speaker still active after 60 s without an edge is `activity_stale`. No floor decision is made here; `FloorAction` is #81.
* *Metrics.* `SpeechObservationMetrics` (observation age, rejects by reason, speaker high water, fallback signals per silence episode, provider unavailable) appears as `RuntimeRetentionSnapshot::speech` when `ProductionApp::with_speech_observations` is composed; it is absent by default.
* *Replay.* `examples/speech-observations/replay/*.json` run through `SpeechReplayFixture` with logical time and no microphone or model; `cargo test --locked -p aivtuber-runtime speech`.

== Speech sidecar (issue #92, S2)

`speech-vad-sidecar` (crates/adapters, `src/bin/speech-vad-sidecar.rs`) turns a local microphone, or `--input-wav`, into `speech-observation` batches on stdout, one JSON line per raw speech edge. The app spawns it as a child process when `AIVTUBER_SPEECH_SIDECAR` is set; it is off by default.

Pipeline: capture (cpal) -> mono -> rubato sinc resample to 16 kHz -> 512-sample (32 ms) frames -> Silero VAD v6 probability -> start/end hysteresis (0.5 / 0.35, the EXP-0001 values) -> raw edge -> stamp on the runtime timeline -> bounded stdout writer. There is no debounce and no minimum-speech filter (ADR-0005): one frame above the start threshold is an edge. No turn-end score is emitted (Smart Turn is not adopted); `language` is declared with `--language`, never inferred.

=== Build and run

[source,sh]
----
# Fetch the pinned model once (sha256 is checked again at every start).
curl -L -o silero_vad_op18_ifless.onnx \
  https://raw.githubusercontent.com/snakers4/silero-vad/v6.2.3/src/silero_vad/data/silero_vad_op18_ifless.onnx
sha256sum silero_vad_op18_ifless.onnx   # 7671cd04b004e9076da0d4a7b1a5aec36adf161c39230c1cb94a4fd5db6bbd28

cargo build --release --locked -p aivtuber-adapters --features silero-vad,mic-capture --bin speech-vad-sidecar
export AIVTUBER_SPEECH_SIDECAR=target/release/speech-vad-sidecar
export AIVTUBER_SPEECH_SIDECAR_ARGS="--model silero_vad_op18_ifless.onnx --language ja"
cargo run --locked -p aivtuber-app      # reads content on stdin as usual
----

* `AIVTUBER_SPEECH_SIDECAR_ARGS` is split on whitespace and passed without a shell (paths with spaces are not supported; at most 32 arguments). `AIVTUBER_SPEECH_SIDECAR_RESYNC_MS` (default 5000, 250 to 60000) sets the steady-state clock re-sync. The child's environment has every `AIVTUBER_*` variable removed.
* Sidecar flags: `--model`, `--language` (required), `--speaker-id` (default `mic-local`), `--input-device NAME` (substring match; `--list-devices` prints names to stderr), `--input-wav FILE [--pace realtime|max]`, `--preroll-ms` (default 300, at most 2000), `--start-threshold` / `--end-threshold`, `--clock sync|local`, `--sync-timeout-ms`, `--duration-secs`, `--stats-secs`, `--clock-probe-ms` (model-free clock measurement mode).
* `mic-capture` is a separate feature because cpal needs ALSA development headers on Linux. Without it `--input-wav` still works. The default workspace build compiles neither feature.
* Manual smoke and clock measurement: `cargo run --release --locked -p aivtuber-app --bin speech-sidecar-check -- --wide --duration-secs 30 -- <sidecar and its flags>` prints every edge with its signed lag (`now_ms - observed_at_ms`) and the tracker metrics. `--wide` widens the tracker limits to 1 s so every edge is measured.

=== Runtime model decision (adopt tract; ort not needed)

Silero VAD v6.2.3 runs through `tract-onnx` 0.23.10 (pure Rust, MIT OR Apache-2.0, no build-time network, no native library). The standard `silero_vad.onnx` cannot be loaded by tract (it analyses both branches of the sample-rate `If` node and fails on the 8 kHz branch), so the pinned asset is the same release's `silero_vad_op18_ifless.onnx` (16 kHz only, no `If`; MIT, snakers4/silero-vad tag v6.2.3, sha256 `7671cd04b004e9076da0d4a7b1a5aec36adf161c39230c1cb94a4fd5db6bbd28`). Measured on 9 EXP-0001 inputs (3 Common Voice ja clips, 3 clean and 3 noisy synthesized streams; 1620 frames), maximum absolute difference of per-frame probability against onnxruntime 1.31.1 running the standard v6 model: ifless export on onnxruntime 4.8e-7, tract on the ifless export 8.7e-7, 0 of 1620 frames differing at the 0.5 threshold. (The probabilities were printed to six decimals, so the true differences are smaller.) tract takes about 0.14 ms per 32 ms frame on the development host (release build of the probe, 130 frames in 18.8 ms), the same order as the 0.22 ms onnxruntime figure in EXP-0001. Decision: adopt (tract, project-owned frame/edge logic). Fallback, if a later Silero export tract cannot load: `ort` with dynamic loading of an operator-installed, pinned onnxruntime (no build-time download). Scores are Silero v6 only: the sherpa-onnx release asset (a v4 export) behaved badly under noise in EXP-0001 and must not be substituted. The model file is never committed; `provider_version` records the model release, the export and the runtime (`silero-vad-v6.2.3-ifless-tract-0.23.10`) because both can move scores.

=== Privacy

* Audio stays in process memory. The sidecar opens no file for writing and no socket; the only output is the observation lines (edges, times, an optional frame confidence), which cannot carry samples. `--input-wav` only reads.
* The only audio kept beyond the frame being scored is `PreRoll`, a bounded in-memory ring of the most recent 16 kHz mono samples (`--preroll-ms`, default 300, hard cap 2000). It is the hook S3 transcription will read to recover onset the VAD reports late (EXP-0001: 12.7% of clean utterances had onset lag above 100 ms). Nothing reads it in S2, it is cleared on a capture gap, and its `Debug` output shows lengths only.
* Tests that need a WAV generate synthetic signals in memory and write them under the cargo test temp directory; no recorded audio and no model is committed.

=== Timeline and clock mapping

The app writes `{"clock_sync":{"runtime_now_ms":N}}` (its own monotonic `now_ms`) to the child's stdin at spawn, every 50 ms for the first 10 s (a line written at spawn is read only after the child starts and loads its model, so the first lines are stale by the startup time; measured 11 to 18 ms with no model, longer with one), then every `AIVTUBER_SPEECH_SIDECAR_RESYNC_MS`. The sidecar keeps `offset = runtime_now - local_receipt_time` over its last 8 syncs and uses the maximum, because pipe delay only ever lowers a sample. Capture positions are mapped to local time by the least-delayed recent chunk arrival (a min filter over the last 256 callbacks), which also tracks drift between the audio device clock and the monotonic clock. Without a first sync the sidecar exits instead of stamping (`--clock local` is for standalone runs). When stdin closes the sidecar exits.

Measured (A-SPEECH-OBS-001): see the assumption entry. Stamp-to-arrival lag of a model-free probe edge, after the warm-up, median 0.3 ms and maximum 0.9 ms in repeated runs (one run showed a single 25 ms scheduling outlier); the lag includes the pipe latency, so it upper-bounds the offset error. Real edges lag their stamp by about 38 ms (32 ms frame start plus the 10 ms capture chunk, then inference), against the 160 ms activity age limit. Not measured: acoustic and device-buffer latency before the callback runs, which needs a loopback rig; the sidecar stamps at callback arrival. The floor therefore sees edges slightly later than the sound, and never earlier.

=== Failure and bounds

* The child's stdout is read by a dedicated thread through the same bounded line reader as the stdin ingress (`pump_bounded_records`; lines over 16 KiB are drained and dropped, at most 64 lines queued, newest dropped and counted). Each poll ingests at most 64 lines, so a flooding child cannot starve the loop.
* The app counts `provider_unavailable` once and stops expecting observations when the child exits, closes stdout, cannot be started, or sends 32 consecutive rejected lines (garbage, or batches refused by the operator ingress ceiling, which applies to `speech` exactly as in S1). There is no automatic restart. A silent child is not a failure: silence is normal. A child that hangs without exiting is not detected (the sidecar has no heartbeat; recorded as a limitation).
* Inside the sidecar: the audio callback uses a bounded channel and counts dropped chunks; a drop closes any open segment, resets the model, resampler and clock, and restarts the stream, so a gap is never spliced. Output goes through a 64-line bounded writer (drop-newest, counted); a closed stdout ends the process.

== Generative fallback configuration

The executable constructs the production `GenerativeRuntime` only when `AIVTUBER_GENERATIVE_ENABLED=true`. Enabling it requires `AIVTUBER_OPENAI_API_KEY` and `AIVTUBER_TTS_ENDPOINT`; endpoint/model/timeouts and optional TTS credentials are documented in `docs/generative-fallback.adoc`. The runtime compatibility values used by generated assets are the same compiler/voice/avatar/viseme/motion values used by the production `AssetStore`.

A `PlaybackRoute::Generate` is produced by the reflex composition when Jev executes the LLM route. Generation is submitted to the bounded `GenerativeRuntime` worker and returns immediately to the composition loop; `tick()` drains completed immutable results, revalidates publication/cancellation state, and only then mutates the hot asset store or scheduler. Slow providers therefore do not stop scheduler advancement or adapter maintenance. The default execution boundary has one in-flight provider job and eight queued jobs; saturation deterministically uses the preselected cached/non-verbal fallback rather than spawning unbounded work. A completed result that has been handed over but not yet drained is still counted as outstanding work, so health, retention, and benchmark waits never observe a false idle state (issue #177).

== Composition profiles (issue #55)

`AIVTUBER_MODE` names the active route graph explicitly. The mode — not disconnected environment flags — determines which planner, semantic index, Jev adapter, template pack, and generative runtime are composed. Startup prints a non-secret summary line (`composition profile: profile=... fingerprint=...`), and the fingerprint is recorded in benchmark result documents (`configuration.runtime_profile`) so base/head comparisons compare like-for-like compositions.

Profiles:

* `cached` (default) — exact/preselected cached playback via `IntentRoutePlanner` only. No semantic retrieval, Jev, templates, or generation.
* `reflex` — semantic retrieval + Jev + curated template decisions via `ReflexRoutePlanner` with the starter template pack. No generative fallback.
* `full` — the reflex route graph plus the LLM/TTS generative fallback.

Profiles fail fast on misleading configurations before composition:

* `reflex`/`full` without `AIVTUBER_JEV_API_KEY` refuse to start instead of silently degrading.
* `full` without a fully configured generative backend (`AIVTUBER_GENERATIVE_ENABLED=true` plus thinking/TTS endpoints) refuses to start; use `reflex` for the documented degraded fallback.
* `cached` with a configured generative backend is rejected as misleading — either select `full` or remove the configuration.

Minimal commands:

[source,shell]
----
# cached (default; no extra credentials needed)
cargo run -p aivtuber-app

# reflex
export AIVTUBER_MODE=reflex
export AIVTUBER_JEV_API_KEY='<jev key>'
cargo run -p aivtuber-app

# full
export AIVTUBER_MODE=full
export AIVTUBER_JEV_API_KEY='<jev key>'
export AIVTUBER_GENERATIVE_ENABLED=true
export AIVTUBER_OPENAI_API_KEY='<thinking key>'
export AIVTUBER_TTS_ENDPOINT='https://tts.example/v1'
cargo run -p aivtuber-app
----

All profiles still require `AIVTUBER_MEMORY_PSEUDONYM_KEY_HEX`; VTube Studio/OBS and the remaining tuning variables apply unchanged to every profile.

== Operator control (issue #56)

The daemon can expose a local, authenticated operator control endpoint for emergency stop/mute and a health/status snapshot. It is enabled by default on the endpoint name +aivtuber-operator-control+ and can be renamed with:

[source,shell]
----
export AIVTUBER_CONTROL_ENDPOINT='aivtuber-operator-control' # optional
----

The transport is an interprocess local socket: a named pipe under the `\\.\pipe\` namespace on Windows and a Unix domain socket on Unix-like systems. It is local-machine scope by construction and cannot be accidentally exposed to the network (no TCP is involved).

Authentication uses +AIVTUBER_CONTROL_SECRET+ (exactly 32 UTF-8 bytes; if unset, the daemon generates a random session secret). Operator clients present the same secret. If the daemon runs with VTube Studio enabled, the value is shared with the avatar adapter boundary by design.

Actions:

[cols="1,3,2"]
|===
|Action |Effect |Authority

|+status+
|Adapter health, mute state, content queue depth, scheduler item count, generation activity. Contains no secret material.
|Secret verification only (constant time); no control authority is minted.

|+stop+
|Stops and cancels current and queued performer work through +SecurityRuntime::handle_control_with_scheduler+.
|+performer.stop+ capability.

|+mute+
|Latches the operator mute state; scheduled audio dispatch is suppressed while muted.
|+performer.mute+ capability.
|===

*Unmute is intentionally not supported.* Mute is a latching emergency state: resuming output requires restarting the daemon with a verified configuration. This is a deliberate choice so a compromised operator session cannot silently re-enable output.

CLI client (clap-based):

[source,shell]
----
export AIVTUBER_CONTROL_SECRET='0123456789abcdef0123456789abcdef'
cargo run -p aivtuber-app --bin aivtuberctl -- status
cargo run -p aivtuber-app --bin aivtuberctl -- stop
cargo run -p aivtuber-app --bin aivtuberctl -- mute
----

Security properties:

* Operator commands never enter the untrusted content queue; they are applied directly on the runtime thread through the same emergency path as operator hotkeys.
* Privileged actions pass through +LocalControlIngress::authenticate+ (constant-time secret comparison, action allowlist, scoped capability minting) before reaching the scheduler; content events cannot forge control authority (ingress rejects any serialized +OperatorCommand+ / authorization metadata).
* Requests are token-bucket rate-limited (burst 16, refill 8/s); the endpoint has its own bounded queue so saturated content ingress, blocked generation workers, or disconnected adapters cannot starve emergency control.
* The secret is never written to logs, telemetry, audit records, or status output. Audit records use the shared redactor.
* Transport failure (listener error, dropped connection) cannot corrupt scheduler/runtime state: requests are applied atomically on the runtime thread and connections are stateless.

== Support bundle / diagnostics (issue #68)

`aivtuberctl diagnose` captures a bounded, privacy-safe support bundle over the same local operator endpoint as `status`. Authentication is the same constant-time secret verification (no control authority is minted), so generating a bundle cannot stop, mute, or otherwise disturb the runtime.

[source,shell]
----
export AIVTUBER_CONTROL_SECRET='0123456789abcdef0123456789abcdef'
cargo run -p aivtuber-app --bin aivtuberctl -- diagnose > support-bundle.json
----

The bundle is a single versioned JSON document (`schema_version` in the manifest, currently `0.1.0`) containing:

* runtime/build/config identity: git revision (best effort), rustc/OS/arch, composition profile, non-secret config fingerprint, asset pack/compiler versions, semantic retriever identity, provider/model **names** (never keys or endpoints);
* adapter health (redacted error text; endpoint URLs are masked as `[ENDPOINT]`);
* bounded resource counters from #51/#52/#53 (queue depths, scheduler active/terminal counts, hot-cache occupancy, audit/telemetry/trace retention, generation worker counts);
* the most recent incident references (correlation ids only) with their redacted #65 causal timelines (one line per stage, no payloads);
* bounded redacted audit summaries (category + decision codes only, newest last);
* a manifest with generation timestamp and a SHA-256 of the bundle body for integrity comparison.

Identity sources (issue #167):

* `composition_profile` and `config_fingerprint` are the daemon's live values — the same ones printed by the startup `composition profile:` line — so an attached bundle is attributable to the composition that produced it. An app composed outside the daemon reports `unknown` for both.
* `git_revision` and `rustc_version` are best-effort compile-time values read from `AIVTUBER_GIT_REVISION` and `AIVTUBER_RUSTC_VERSION` when the binary is built. The default build path does not set them, so they report `unknown` unless the builder provides them. To build an attributable release binary:

[source,shell]
----
AIVTUBER_GIT_REVISION="$(git rev-parse HEAD)" \
AIVTUBER_RUSTC_VERSION="$(rustc --version)" \
cargo build --locked --release
----

Privacy model — the exporter is allowlist-based:

* it serializes explicit typed fields only; it never dumps environment variables, configuration files, payloads, transcripts, durable memory, or viewer identifiers;
* payloads and actor ids never enter causal traces or the correlation registry, so they cannot reach the bundle through them;
* every audit record has already passed the shared secret redactor at write time, and adapter error text is redacted again at export time;
* bundle generation is synchronous local work over already-retained state: no external provider calls, no unbounded history retention, and no scheduler/control mutation, so it works while providers are down and never blocks emergency control.

Bounds: causal timelines default to 8 and audit summaries to 32; both are clamped to 256 and configurable via `SupportBundleBuilder`. The correlation registry on `SecurityRuntime` retains at most 128 references.

Reproducibility workflow: follow link:after-action-review.adoc[After-Action Review and Regression Learning]. Attach the bounded bundle JSON to the incident issue when appropriate. The correlation ids inside map 1:1 to `trace_for_correlation` lookups in a replay; the identity section decides whether two bundles are comparable (same profile fingerprint and compiler version) before comparing counters.

Limitations: the bundle is evidence, not a replay artifact. It does not include private conversation text by design, so some behavioral incidents will need a separate minimal reproduction case.

== End-to-end interaction deadlines

Every admitted content event receives a trusted runtime deadline class derived from its normalized `EventKind`; untrusted payload fields do not choose or extend the class. Operator commands remain on the independent authenticated control path and do not enter this content-deadline policy.

The current classes are `high_priority`, `strong_reaction`, `conversation`, `commentary`, and `background`. `InteractionDeadlinePolicy` owns their budgets and the minimum useful budget required before starting generation. The default 30-second values are conservative safety ceilings that preserve existing behavior; they are not latency SLO targets and should be calibrated by #58 before tightening production profiles.

One interaction budget spans routing and provider work. Retrieval time is subtracted before Jev admission. OpenAI-compatible Thinking, normalized HTTP TTS, and Jev each receive an effective timeout no larger than both their provider-specific maximum and the remaining interaction budget. If too little useful budget remains before generation, production selects the already-determined cached/non-verbal fallback without entering the provider worker. A generation completion that arrives after the useful deadline is discarded at the composition-thread commit fence and cannot insert a hot asset or schedule playback.

The immediate interaction deadline is distinct from any future deferred-response expiry (#75): missing the immediate useful-time budget vetoes immediate work, but does not by itself define whether a separately retained deferred item is still contextually valid.

== Generative resource budgets (issue #69)

The generative resource budget is a provider-neutral admission policy that sits **before** generation submit: a denial never allocates provider work that must then be cancelled. It is disabled by default — existing deployments keep identical behavior until it is enabled explicitly.

[source,shell]
----
export AIVTUBER_BUDGET_ENABLED=1
export AIVTUBER_BUDGET_INTERVAL_MS=60000
export AIVTUBER_BUDGET_MAX_CONCURRENT_GENERATIONS=2
export AIVTUBER_BUDGET_MAX_LLM_CALLS=30
export AIVTUBER_BUDGET_MAX_TTS_CALLS=30
# Optional finer-grained ledgers:
export AIVTUBER_BUDGET_MAX_LLM_UNITS=200000
export AIVTUBER_BUDGET_MAX_TTS_CHARS=20000
# Optional cost ceiling (requires a pricing input version):
export AIVTUBER_BUDGET_MAX_COST_MILLIUNITS=500
export AIVTUBER_BUDGET_PRICING_INPUT_VERSION=pricing-2026-09
# Share of every call budget reserved for high-priority deadline classes:
export AIVTUBER_BUDGET_RESERVE_PERCENT=25
# Whether #64 shadow evaluation spends billable budget (default: no):
export AIVTUBER_BUDGET_CHARGE_SHADOW=0
----

Semantics:

* all ledgers roll over `AIVTUBER_BUDGET_INTERVAL_MS` using the runtime's logical clock, so recorded decisions replay identically;
* priority comes **only** from the trusted #67 deadline class (`high_priority`/`strong_reaction` may spend the reserved share); untrusted content fields can never promote priority;
* on denial the request degrades deterministically — reuse → semantic/template → cached/non-verbal → safe silence — exactly like other fallbacks, with a typed reason (`concurrent_budget_exhausted`, `llm_call_budget_exhausted`, `tts_call_budget_exhausted`, `llm_unit_budget_exhausted`, `tts_char_budget_exhausted`, `cost_budget_exhausted`) that stays distinct from #67 deadline exhaustion and #121 `capacity_saturated`;
* granted reservations settle with observed TTS usage at commit time and release automatically on stale/cancelled completions, so enforcing the budget never strands provider work or leaks in-flight slots;
* #64 shadow evaluation does not consume billable budget unless `AIVTUBER_BUDGET_CHARGE_SHADOW=1`;
* operator emergency control (stop/mute/diagnose) runs on the independent authenticated control path and is budget-independent by construction.

Accounting is observable in three places: the support bundle's `resources.generative_budget` section (six bounded budget-type records with limit/consumed/remaining/rejected_or_degraded), the telemetry `budget_denial_reason` column, and the `budget_denied` audit records with typed reasons.

== VTube Studio output

Enable VTube Studio only when its local websocket API is available:

[source,shell]
----
export AIVTUBER_VTS_ENABLED=true
export AIVTUBER_VTS_ENDPOINT=ws://127.0.0.1:8001
export AIVTUBER_CONTROL_SECRET='0123456789abcdef0123456789abcdef'
# Optional when reusing an existing VTube Studio token:
export AIVTUBER_VTS_TOKEN='<token>'
----

The control secret must be exactly 32 UTF-8 bytes. It is used only to mint the existing non-serializable local +AuthenticatedControl+ authority required by the avatar adapter boundary.

Cached expression and gesture presets map to VTube Studio hotkeys using the preset name. Gaze commands default to hotkeys named +gaze.<target>+. Visemes map to injected parameters +VisemeA+, +VisemeI+, +VisemeU+, +VisemeE+, +VisemeO+, and +VisemeN+.

The corresponding VTube Studio hotkeys/parameters must exist in the local model/profile.

== OBS output

OBS is optional:

[source,shell]
----
export AIVTUBER_OBS_ENABLED=true
export AIVTUBER_OBS_ENDPOINT=ws://127.0.0.1:4455
export AIVTUBER_OBS_PASSWORD='<obs-websocket-password>'
----

Startup or reconnect failure is recorded as degraded adapter health. It does not stop cached scheduling.

== Local cached-path live smoke

Prepare at least one real starter audio file under the configured audio root and configure the corresponding VTube Studio hotkeys/viseme parameters.

Then run:

[source,shell]
----
AIVTUBER_AUDIO_ROOT=/path/to/materialized/audio \
AIVTUBER_VTS_ENABLED=true \
AIVTUBER_CONTROL_SECRET='0123456789abcdef0123456789abcdef' \
cargo run -p aivtuber-app
----

Paste a valid content Event Envelope as one line, for example:

[source,json]
----
{"schema_version":"0.2.0","event_id":"evt-live-1","correlation_id":"corr-live-1","sequence":1,"observed_at":"2026-09-24T00:00:00Z","source":"local-smoke","source_class":"public_chat","plane":"content","trust_level":"untrusted","kind":"chat.message","actor_id":"viewer:smoke","priority_hint":null,"payload":{"text":"hello","intent":"reaction.agree"}}
----

Expected behavior:

. ingress reports +Queued+;
. a compatible +reaction.agree+ asset is selected without LLM/TTS;
. audio is launched by the configured player at its scheduled time;
. expression/gesture/viseme/gaze commands are sent to VTube Studio;
. VTube Studio or OBS failure does not freeze scheduler progress.

To include OBS in the same smoke, also set the OBS variables above. OBS is not required for cached avatar/audio playback.
