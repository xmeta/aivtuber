A candidate becomes the current measured constraint only when the evidence packet below supports it and the intervention is actionable.

== 6. Reprioritization rules

Revisit the current constraint when one or more of these occur:

* #97 completes representative provider/live-smoke evidence or exposes a release-blocking incident;
* a major issue aimed at the current constraint closes;
* a compatible #58 benchmark trend changes materially beyond expected variance;
* #40 fault/soak evidence exposes a different limiting failure mode;
* #59 quality evaluation identifies a dominant quality regression;
* #71 shows a persistent operational SLO miss;
* a provider/platform/dependency change invalidates a load-bearing assumption;
* the current intervention reaches its target/plateau or shows low marginal value.

Do not reorder priorities from one noisy run or an incompatible benchmark series.
Separate the strategic roadmap from this tactical constraint statement: roadmap capability direction may remain valid even when the current measured bottleneck moves.

Hard security, privacy, authorization, operator-control, stale-dispatch, and bounded-state constraints remain binding regardless of the selected bottleneck.
