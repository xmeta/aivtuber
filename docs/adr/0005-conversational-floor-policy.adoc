= ADR-0005: Deterministic conversational-floor policy with reversibility-tiered timing and tentative interruption
:status: Proposed
:date: 2026-11-08

== Context

Issue #81 asks for a provider-neutral conversational-floor layer that decides when the performer should hold, yield, backchannel, take a turn, interrupt, or wait, separately from deciding what to say.
It is +status:design-ready+: this ADR records a candidate decision, a reuse review of four public projects, and a throwaway replay simulation. It authorizes no production code and adds no dependency.
The throwaway simulator is committed under link:../../examples/benchmarks/floor-sim/README.md[+examples/benchmarks/floor-sim/+] (it reads the EXP-0001 work directory; no data; CI does not run it); the numbers and the design are recorded here. Supervisor decisions are in the subsection of that name under Decision.

Inputs this ADR builds on, all merged on +main+ at +d78d714f+:

* link:../experiments/EXP-0001-japanese-turn-observation-bench.adoc[EXP-0001] (#92): VAD-derived speech activity is usable; Smart Turn v3.2 was not better than a fixed silence timeout on Japanese; the supervisor decisions carry the reversibility-class question to #81 (11.1 item 5) and make the turn-end value an optional score with a +calibrated+ flag that defaults to false (11.1 item 3).
* link:0004-speech-lifecycle-and-text-projection.adoc[ADR-0004] (#222): +SpeechLifecycleEvent+ with +phase+, +phrase+, +final_phrase+ and +basis+; decision D-6 says #81 must read +basis+ and must not treat +LogicalTimeline+ as audible.
* link:0003-local-vrm-renderer.adoc[ADR-0003] (#219): the avatar already exposes symbolic +Expression+, +Gesture+ (nod), +Gaze+ commands, so non-verbal backchannels have an output path; measured command-to-rendered-frame latency is 15 to 17 ms on a GPU and about 111 ms on software GL, plus a 60 ms interpolation time constant.
* the existing scheduler (+crates/scheduler/src/lib.rs+): +Priority+ ranks (Operator 0 to Background 5), preemption rejected when +incoming_rank > playing_rank+ (+:526-531+), +next_safe_boundary+ over declared +interrupt_points_ms+ (+:745-756+), +min_reaction_spacing_ms+ default 1500 (+:185,197+), and a +cancel_at_ms+ that is set when a plan is preempted. There is no pause or resume primitive.
* the speculative-preparation rule in link:../architecture.adoc[architecture 6.3.1]: preparation is data, never public output, and only a deterministic commit path may make it irreversible.

Today a generated reply declares exactly one interrupt point, at the end of the speech (+crates/generative/src/lib.rs:479+, see also ADR-0004 lifecycle table). That matters for the barge-in numbers below.

== Hard constraints

* Model, Jev and generated output are data, never runtime authority. Jev may recommend a floor action; the deterministic policy decides (issue #81 non-goal: Jev must not stop or dispatch scheduler actions).
* Untrusted content cannot declare itself interrupt-critical. Source class, trust and priority are assigned by the normalizer, never by the payload.
* Operator emergency stop is an independent control path and is not routed through the floor policy or its state.
* The scheduler owns cancellation, safe interrupt points, priority arbitration and generation fencing. The floor policy never cancels or dispatches directly. (Supervisor decision S-3 lets the scheduler stop the audio of a confirmed voice barge-in at a non-safe point with a bounded fade-out; the scheduler still executes it.)
* Nothing speculative becomes public except through the deterministic commit path (architecture 6.3.1).
* The policy runs outside the frame/motor loop and is a pure function of its inputs; replay uses logical or monotonic ordering, not wall-clock ordering.
* All retained state is explicitly bounded (decision log, backchannel history, outstanding preparations).
* Provider-specific DTOs stay behind adapters; the floor contract must not hard-code one VAD, VAP or turn-detection provider.
* Raw audio does not enter the domain contract (EXP-0001 guardrail).

== Assumptions

No existing assumption ID covers floor timing. Proposed new assumptions (to be added to the link:../assumptions.adoc[Assumption Register] if this ADR is accepted):

* A-FLOOR-001: A silence ladder over VAD observations, with the irreversible TakeTurn at about 800 ms, is an acceptable first floor policy for Japanese speech until real labelled dialogue exists. Evidence: EXP-0001 and section Results below, both on synthetic constructions. *Not validated on real conversation*; this is the principal falsifier for the implementation phase.
* A-FLOOR-002: A non-verbal backchannel (gaze, face, nod) at about 300 ms of silence is not perceived as annoying, while a spoken one on the same trigger is. Evidence: none beyond the mechanical overlap measurements below. Needs a human-rated #59 sample.
* A-FLOOR-003: Attenuating the performer ("duck") on a tentative interruption, and restoring it on a false one, is acceptable without a pause primitive in the scheduler. Evidence: none; the ducked durations below are model outputs, not listener judgements.
* Related existing IDs: A-AUDIO-001 (output-adapter return is not acoustic first-audible time) and the proposed A-SPEECH-003 from ADR-0004.

== Alternatives considered

. *Status quo*: speak whenever a reply is ready; the only interruption is operator stop. Rejected as the end state: the issue exists because this is not a floor policy.
. *Fixed silence timeout only* (one threshold, one action). The baseline. Cheap and predictable but forces one trade-off for all actions: at 800 ms the lag at a true end is about 870 ms; at 500 ms 39 percent of holds are cut (section Results).
. *Delegate turn and interruption handling to LiveKit Agents or Pipecat as the orchestrator.* Rejected: both frameworks own interruption and cancellation inside their pipelines (LiveKit pauses and cancels the speech handle, Pipecat broadcasts an interruption on turn start), which conflicts with scheduler authority, the lifecycle truth rules of ADR-0004 and the commit barrier. Their state machines and defaults are reused as references only.
. *Model-driven turn-end (Smart Turn, Jev, a VAP-style model) as the commit trigger.* Rejected for now: EXP-0001 found no model-based claim confirmable without a real labelled Japanese turn set (11.1 item 1), and Smart Turn fired on 83 to 85 percent of holds. A model score is admitted only as an optional, flagged input that may start reversible work.
. *Pause and resume of the performer's audio* (LiveKit's false-interruption recovery). Not adopted in the first slice: it needs a pause primitive in the scheduler and output adapters that does not exist, and a paused-then-resumed phrase makes lifecycle +Started/Boundary/Finished+ truth ambiguous. A reversible attenuation (duck) gives the same recovery property without touching the timeline. Revisit if listener tests reject ducking.
. *Reversibility-tiered deterministic policy (proposed)*: separate thresholds by how costly the action is to take back; early preparation, late commit; tentative then confirmed interruption.

== Evidence

=== Method

A throwaway pure function +decide(state, observation, own_speech, event, config) -> (state, decision)+ was written in Python (committed as scripts under +examples/benchmarks/floor-sim/+) and replayed over the saved EXP-0001 per-frame Silero v6 speech probabilities for the same 424 labelled streams (A 142, B1 80, B2 114, C 88), in the clean and the noisy15 conditions (EXP-0001 4.2; seed 20261108). The observation adapter applies the EXP-0001 hysteresis (on at 0.5, off at 0.35) frame by frame and delivers each observation only at the end of its 32 ms frame, so the policy is causal. Smart Turn scores from the same saved run were used where stated, delayed by 120 ms (about the measured inference p95) before they are visible.

*The data are synthetic.* Streams are read Common Voice sentences with inserted silences of exactly 300, 500 or 700 ms (EXP-0001 4.3, 9). They contain no breath, filler, overlap, backchannel, cough, laughter or game audio. Every limitation L1 to L14 of EXP-0001 applies here, and the absolute rates must not be read as production rates; only the ordering of policies and the mechanisms are claimed.

*Reproduction check.* Applying EXP-0001's own +ev_fixed+ rule (min-speech-filtered segments with an oracle next-segment start) to the saved scores reproduced its published clean counts exactly: false take on holds 145/194 at 300 ms, 83/194 at 500 ms, 7/194 at 800 ms (noisy15: 142, 72, 7). The causal policy in this ADR gives fewer false takes at 800 ms (1/194 clean, 6/194 noisy15) because it treats any raw VAD run, however short, as activity that resets the silence clock. In all six clean streams where the two rules differ at 800 ms (B1_046, B1_064, B1_073, B2_023, B2_056, B2_098) a raw VAD run shorter than the 250 ms minimum (32 to 224 ms) lies in or next to the pause. Whether such a fragment is real speech or a pause-construction artifact cannot be decided from this data, so *both numbers are reported* and the finding is carried as a requirement on #92 (D2): the observation must expose raw activity without the 250 ms debounce, or the floor cannot see these cases.

Assumed parameters (not measured, all configurable in the sim): a spoken backchannel asset lasts 400 ms; duck takes 50 ms to apply after a decision and a scheduler dispatch takes 50 ms; a synthetic performer reply is 8 s long; "phrase" boundaries are spaced 1.2 to 2.4 s, "fine" boundaries 0.6 s, "none" means the single end-of-speech interrupt point that generated replies declare today; the preparation time P of LLM plus TTS is swept at 300, 600, 1000 and 1500 ms. Ten random phase offsets per stream give 3360 barge-in trials per condition; they are not independent draws.

Findings:

. A vocal backchannel fired from the silence ladder lands before the take on essentially every true end (100 percent with a 1 s minimum). That is "a spoken filler for every wait", an explicit #81 non-goal. Requiring 3 s or 5 s of preceding speech reduces it to 55 and 22 percent of ends in this data, because these sentences are 1.2 to 9 s long; the number tracks the data, not a general rule.
. Every vocal backchannel that landed on a hold overlapped the resumed speech (median 272 ms of 400 ms). This is a consequence of the three-valued pause distribution, because a hold that survives 500 ms must resume before the 800 ms take; with real, continuous pause lengths some would clear. It does not say a short vocal acknowledgement is acceptable when it overlaps.
. A non-verbal backchannel at 300 ms precedes 73 percent of holds and 99 percent of true ends. It is cheap to take back (D3) but would be a nod before almost every reply; whether that reads as attentive or mechanical is a persona and #59 question. Japanese aizuchi frequency norms were not studied here.
. The tier structure does not change the TakeTurn false rate or lag at all (by construction). Its measurable benefit in this data is only that something visible happens at about 330 ms instead of 870 ms; whether that is perceived as responsiveness was not tested.

=== Results: early prepare, late commit (policy 3)

Preparation starts at threshold E of silence; the result stays speculative; commit is still at 800 ms; preparation is cancelled when raw speech resumes. Lead time is commit time minus preparation start. Because the commit rule is fixed, the lead is *deterministic*: 800 minus E plus the 32 ms frame quantum, with no spread (p10 = p50 = p90). What varies is the waste.

Findings:

. The saving is *min(P, lead)*. Early preparation cannot hide a preparation longer than 800 minus E: with E = 400 ms it removes 300 to 384 ms of a 600 to 1500 ms LLM-plus-TTS time, and a 1.5 s preparation still ends 1984 ms after the end of the user's speech. It makes a 300 ms preparation free, not a 1.5 s one. Hiding more needs streaming inputs (partial transcripts, phrase-level output, #83) or reversible masking (#82).
. The cost is real: at E = 400 ms two out of five turn ends are accompanied by a wasted preparation (and 68 percent of holds cancel one). Pipecat leaves the equivalent feature off by default for this reason, and LiveKit caps it at 3 attempts, skips long speech and does not run TTS preemptively. The design keeps those bounds.
. A Smart Turn trigger cancelled 18 percent fewer preparations than a 300 ms timer at the same median lead (124 versus 152 cancelled), but gave no early preparation for 6 percent of true ends (20/336) and costs 94 ms of CPU per inference (EXP-0001). This is within what 194 holds can resolve, and it is consistent with the AUC of 0.64 in EXP-0001; it is not evidence for adopting the model.

Findings:

. Cancelling on the first activity (the common default) turns every short sound into a cancelled reply. A tentative stage removes that for bursts shorter than the confirmation threshold, at the price of confirm latency: 400 ms costs about 320 ms more than a hard cancel. The threshold is a cough-versus-speech trade, and 400 ms sits at the same order as LiveKit's 500 ms +min_duration+.
. *Yield latency is dominated by safe-point density, not by detection.* Detection plus confirmation is 0.2 to 0.5 s, but the audio stops at the next declared interrupt point: about 1.4 s at phrase granularity, 0.8 s at 0.6 s granularity, and 4.8 s (p50) against the single end-of-speech point that generated replies declare today. Until #83 phrase streaming (or asset-declared finer interrupt points) exists, a confirmed barge-in cannot be honoured quickly by a policy that respects safe points, and the duck is the only immediate cue. Supervisor decision S-3 answers this with a bounded fade-out for confirmed voice barge-in, and records phrase-level interrupt points as a #83 follow-up.
. The simulated user speech is read sentences that start at a random time; real barge-in speech often begins with a short filler or breath, which the 96 ms tentative run and the debounce question (D2) interact with. Not measured.

=== Results: stale-observation rejection

For each hold, a delivery stall of 600 ms was injected at a random point inside the pause (5 draws per stream, 970 trials). During a stall the policy is still ticked with the last delivered observation. Without a freshness rule the silence clock keeps counting through the stall; with the rule (observation age above 160 ms makes the policy Wait, cancel preparation and withhold TakeTurn) it does not.

[cols="3,2,3",options="header"]
|===
|Condition |False take on holds |Lag at true ends p50 / p90 / p99 (ms), 670 streams with a 600 ms stall within 800 ms after the end
|no stall (reference), clean |1% (5/970; 0-1) |868 / 909 / 979
|stall, no freshness rule, clean |*40% (384/970; 37-43)* |868 / 909 / 979
|stall, freshness rule (age at most 160 ms), clean |1% (5/970; 0-1) |917 / 1241 / 1326
|no stall, noisy15 |3% (30/970; 2-4) |899 / 969 / 1039
|stall, no freshness rule, noisy15 |35% (336/970; 32-38) |899 / 969 / 1039

The rule trades a bounded extra lag (p90 up by about 330 ms when the stall lands at the true end) for removing the dominant failure of a frozen feed. A stall of 600 ms is an assumed magnitude; the point is the mechanism.

=== Results: determinism and the issue's path coverage

The pure function was exercised on 20 rows (idle, speaking, tentative, confirmed, false interruption, stale feed, no VAD, critical trusted event, untrusted critical event, donation, normal chat, busy game segment) and all produced the expected action; 1000 repeated evaluations of the same input returned identical output. This is a sanity check of the sketch, not a measurement: the Jev path and the persona path are not modelled (Jev is advisory and absent from the function). The rows are the seed fixtures for the test plan.

== Decision

Candidate decision, not yet accepted. D1 to D9 are the proposal; the supervisor decisions, which amend D1, D3, D5 and D7 where they differ, are in Supervisor decisions below and prevail.

=== D1. Single owner, placement and boundaries

* A single deterministic +FloorPolicy+ is the only producer of +FloorDecision+. It is a pure function of explicit inputs and configuration; it reads no clock, performs no I/O and holds no randomness. It runs on the control tick, never in the frame or motor loop, and never waits on Jev, a provider or a generation.
* It emits recommendations to existing owners and nothing else: scheduling requests go through the normal scheduler path (so rank checks, cooldowns, +min_reaction_spacing_ms+ and +next_safe_boundary+ apply unchanged); preparation directives go to the generation executor; non-verbal backchannels go through the normal avatar command path (ADR-0003 +Expression+, +Gesture+, +Gaze+). +Yield+ and +Interrupt+ become a preemption request evaluated by the scheduler, whose +cancel_at_ms+ mechanism executes it. The policy cannot cancel.
* Operator stop never enters the policy. Its path stays as it is today; the policy has no input or state that can delay it, and a stuck or panicking policy must not delay it (test in the plan).
* Placement (decided, S-1): types in +crates/domain+ (provider-neutral, bounded, versioned); the policy in +crates/scheduler+ beside arbitration, with access to the lifecycle log. Not the app layer, not an adapter.

=== D2. Types and inputs

Names are implementation choices. Sketch:

----
FloorAction
  Hold | Yield | Backchannel | TakeTurn | Interrupt | Wait

FloorDecision
  seq, at_ms               logical time, per-process monotonic sequence
  action: FloorAction
  reason: FloorReason      closed enum (for replay and metrics; no free text)
  backchannel: Option<{ ladder_level 1..4, intent: BackchannelIntent, speech_allowed }>
  prepare: None | Start { turn_epoch } | Cancel { turn_epoch }
  interruption: NoInterruption | Tentative | Confirmed | FalseInterrupt | Resume
  attenuate: bool          reversible duck while Tentative
  earliest_ms, deadline_ms Option    (issue: earliest turn time, maximum wait)
  attention: AttentionTarget         existing enum
  inputs: { observation seq + age, lifecycle seq + basis, event id, config version, jev hint digest, fallback }

FloorInput
  observation: Option<TurnObservation>   (#92)
  own_speech: view of the latest SpeechLifecycleEvent for the performer (#222)
  event: classified event { scheduler Priority assigned by the normalizer, trust, kind }
  attention, game_busy, bounded backchannel history, config
  jev_hint: Option<JevFloorHint>         advisory, may be absent
----

* *Observation (#92) fields the policy needs.* +speech_active: Option<bool>+ (absent when no VAD); the logical time of the last activity edge and of the observation itself, assigned at ingress by the normalizer, not by the provider; the raw run start; an optional turn-end score object +{ value, provider_id, calibrated }+; the +calibrated+ flag defaults to false and an uncalibrated score is *never* read as a probability and may only start reversible preparation (policy 3 variant). The policy computes silence as logical-now minus the last activity edge, so a provider that freezes cannot extend or shorten it (D6). *Requirement on #92:* expose raw activity edges without the 250 ms minimum-speech debounce; segments filtered by that debounce hide 6 of 194 holds' fragments in this data (Evidence, reproduction check). A debounced "utterance started" flag may exist in addition, as the turn-opening signal.
* *Own speech (#222)* is read through +basis+, as D-6 requires:
** +Prepared+: not speaking. The floor is free.
** +Committed+ and not yet +Started+: the floor is reserved but nothing is audible. A confirmed user interruption cancels without waiting for a boundary (cancel reached +Committed+), which is free.
** +Started+ and +Boundary+: speaking. With +basis = LogicalTimeline+ the policy treats it as speaking for Hold and Yield purposes (conservative) but metrics that name audible overlap are labelled with the +basis+ and not reported as audible truth.
** +Finished+ and +Cancelled+: free, subject to +min_reaction_spacing_ms+.
* *Priority and attention.* Priority is the scheduler's +Priority+ assigned by the normalizer. A user's voice does not outrank the performer's current speech by itself: the policy emits +Yield+ only if the scheduler would accept the preemption (+incoming_rank <= playing_rank+); otherwise it holds and may answer with a non-verbal backchannel. +AttentionTarget+ is both an input and an output: a non-verbal backchannel gazes at the speaker; a busy game segment (+attention = Game+) defers non-critical TakeTurn with a deadline.
* *Semantic response selection is separate*: the input has no response text type, only identities, priorities and flags; whether to speak is floor policy, what to say is generation.

=== D3. Reversibility classes and thresholds (configuration, measured defaults)

The measured trade-off of EXP-0001 and this replay says one threshold cannot serve every action. Each action class has its own silence threshold, bounds and budget, all configuration with validated ranges. Defaults below are starting values to be re-measured on real dialogue (A-FLOOR-001), not tuned results.

|R1 visible non-verbal |gaze shift, face, nod (ladder 1-3) |300 ms (200-500) |one renderer interpolation, about 150 ms visible (ADR-0003) |precedes 73% of holds and 99% of true ends in this data. Spacing budget applies; persona-scalable.

* Persona (#72) selects a *named style class* (for example fast, normal, calm), and a validated table maps the class to values inside the ranges above. A persona never supplies raw thresholds, VAD probabilities or scheduler timings, and any value outside a range is rejected at load, not clamped silently.
* Backchannel *timing* and *type* are separate fields: timing is the policy's decision, +BackchannelIntent+ (Acknowledge, EncourageContinuation, Agreement, Surprise, Sympathy, ThinkingReceipt) is a recommendation, and the pair is satisfied non-verbally when speech is not allowed (intent to gesture or expression mapping lives in the avatar profile, ADR-0003). #59 can score timing error and type error independently from the logged fields.
* Ladder mapping: 0 is +Wait+ or +Hold+, 1 to 3 are +Backchannel+ with +speech_allowed = false+, 4 is +Backchannel+ with a cached asset, 5 is +TakeTurn+.

=== D4. Early prepare, late commit and the commit barrier

* +prepare = Start+ opens a speculative job tagged with a +turn_epoch+. The epoch advances whenever raw user speech resumes or the source event or revision changes. The result is data held outside scheduler state.
* At +TakeTurn+ the existing deterministic commit path revalidates, in this order: the epoch is still current, the source event or revision is current, the remaining deadline and resource policy, the publication-containment gate, and the phrase's atomic commit rules (architecture 6.3.1). Any failure discards the result; a late provider completion after a cancel is discarded by the same fence.
* Speculative work emits no +SpeechLifecycleEvent+ (ADR-0004). +Prepared+ is emitted when the committed path admits the result, so a cancelled preparation is never visible in the lifecycle log and cannot be mistaken for a reply. See Q5.
* The measured limit applies: the lead is 800 minus E, so preparation hides at most 288 to 384 ms; the ADR does not claim more.
* Only the floor policy decides when to prepare; a model score may start preparation only as an uncalibrated hint (D2).

=== D5. Barge-in and false-interruption recovery

* States: +NoInterruption+, +Tentative+, +Confirmed+, +FalseInterrupt+, +Resume+ (the issue's vocabulary). All user speech while the performer is speaking enters +Tentative+ only after a raw run of at least 96 ms. Evidence tiers: duration (default confirm at 400 ms of continuous raw activity); semantic evidence (words, a future ASR adapter, in the manner of Pipecat's +min_words+ and LiveKit's final-transcript commit) may confirm earlier or veto a long run. Configuration, not logic, selects the tier.
* +Tentative+ attenuates the performer (a duck) and changes nothing in the scheduler. Therefore *Resume is only the restoration of attenuation*: no phrase is cancelled or replayed, no generation is created, and generation fencing cannot be violated by recovery. This is the difference from LiveKit's pause and resume.
* +Confirmed+ emits +Yield+, a preemption request executed by the scheduler. Proposed here at the next safe interrupt point (or immediately if the reply had reached only +Committed+, D2); S-3 amends this: a confirmed voice barge-in may stop the audio at a non-safe point with a short bounded fade-out. The lifecycle then records +Cancelled+ with reason +barge_in+ and the heard portion, which is exactly what the lifecycle says was spoken, never client-reported text.
* +FalseInterrupt+ is declared when raw speech ends before confirmation and 500 ms of silence has elapsed; the attenuation is restored. While +Tentative+ the stale-observation rule applies: if the feed stalls, the attenuation is released after a configured maximum duration rather than held indefinitely.
* The state is bounded (a single tentative window per speaking phrase) and recorded in +FloorDecision.interruption+; metrics are tentative count, confirmed count, false-interrupt count, resume latency, incorrectly resumed (restored and then the user held the floor), and incorrectly cancelled (confirmed but the next user input shows it was a backchannel).
* Operator stop remains immediate and outside this machine. Priority outranking is not decided by user speech: a +StrongReaction+ or higher performer segment is held (the scheduler would reject the preemption).
* Whether a hold at a phrase boundary while +Tentative+ is needed (so a next phrase does not start under an unconfirmed interruption) requires a scheduler capability that does not exist (deferred, S-4). Without it a phrase boundary reached while tentative simply continues, attenuated.

=== D6. Stale-observation rejection

* Every observation carries a normalizer-assigned logical timestamp and a monotonic +seq+. Duplicates and out-of-order observations are dropped.
* For decisions that are costly to reverse (TakeTurn, Yield confirmation, Interrupt) the observation must be fresh: age at most 160 ms by default (five frames; range 96-320 ms). A stale or absent observation yields +Wait+ (listening) or +Hold+ (speaking) with a +StaleObservation+ reason, cancels preparation, and never extrapolates the silence clock. Measured: removes 40 percent false takes under a frozen feed at a cost of bounded extra lag (Results).
* A turn-end score has its own time to live which must be at least the inference p99 plus the polling cadence (about 125 plus 100 ms from EXP-0001 section 7). It cannot satisfy the freshness rule for a commit by itself because it never commits.
* The policy requires fresh evidence to leave a protective state. A recovered feed starts with a fresh run (speech or silence) and a new silence clock.

=== D7. Fallback when no VAD is present (text-chat-only mode)

* +speech_active+ is absent. There is no silence clock, so no silence-ladder action exists: the message boundary is the turn end. This keeps the system usable with only the Twitch ingress that is already on +main+.
* A complete, admitted message while the performer is idle yields +TakeTurn+ subject to priority, +game_busy+ (a non-critical message defers with a deadline) and +min_reaction_spacing_ms+. While the performer is speaking, normal chat yields +Hold+ (defer) and at most a non-verbal acknowledgement; it can never yield +Interrupt+. A donation yields an acknowledgement backchannel (ladder 4, allowed because it is event-driven) and a later full turn. A trusted critical game event may yield +Interrupt+ at the next safe point if the asset is interruptible; an untrusted event that merely claims criticality is ranked by the normalizer and held.
* Mid-session loss of the VAD (stale feed beyond a configured duration) degrades to this same path and is recorded as a +VadUnavailable+ fallback reason, never as silence.
* These rows are exercised in the 20-row sanity table above; the busy-game and donation rows are examples of the shape, not final policy.

=== D8. Jev role

* Jev is advisory and asynchronous. The policy never waits for it; it uses the latest hint only while the hint is fresh, otherwise runs with +jev_hint = None+ and records a fallback reason.
* Jev may recommend: an action from the set allowed at the current reversibility class, a +BackchannelIntent+, a strength, an interrupt probability that the tier gate reads as input, and an attention target. It cannot move a threshold below the configured floor of its class, cannot add an action the class forbids, and cannot touch R3 or R4 timing (it may only request a later TakeTurn up to the deadline).
* Jev is *not* in the timing path by default. EXP-0001 11.2 Q7 is unresolved and no model beat the silence baseline in this work; a Jev timing role requires a real labelled turn set first.
* The replay record stores the hint digest, its latency and the fallback reason (issue "Replay" list).

=== D9. Replay and metrics

* Replay inputs are the ordered observation stream, lifecycle events, classified events, hint digests and the configuration version. Re-running reproduces every +FloorDecision+ where Jev is absent or recorded; no wall-clock value is consulted.
* Decision log: bounded ring, privacy rule of ADR-0004 (identities and digests, no free text).
* Metrics map to the issue: time from end-of-turn to turn start (the lag columns), overlap and interruption rate, interruption success and cancel rate (D5 counters), backchannel rate by level, unnecessary spoken-backchannel rate on reviewed samples (needs #59), long-silence-before-response rate, phrase-boundary versus hard-interrupt distribution (the stop columns), Jev latency and fallback, operator and critical-event preemption latency, plus the new counters: cancelled preparations per 100 turn ends, stale-observation waits, and false-take rate on holds when labelled data exists.

=== Supervisor decisions

Recorded after review; the ADR status remains Proposed. These prevail over D1 to D9 where they differ.

. *S-1 (placement)*: the +FloorAction+ and input types go in +crates/domain+ (provider-neutral). The deterministic floor policy goes in +crates/scheduler+ beside arbitration; not in the app layer or an adapter. Closes Q1.
. *S-2 (spoken backchannel)*: off by default until #59 rates it. The non-verbal backchannel (a nod) is on. Closes Q2; the R2 row of D3 is therefore disabled by default, not merely budgeted.
. *S-3 (fast preemption: yes)*: a *confirmed* voice barge-in (after the 400 ms confirmation) may stop the current audio at a non-safe point with a short bounded fade-out (at most 150 ms, configurable). Reason: stopping never publishes new content, so it does not conflict with the commit barrier, which guards starting output, not stopping it. The lifecycle records +Cancelled+ with reason +barge_in+ and the heard-text prefix (the pattern adopted from Open-LLM-VTuber). Closes Q3. Follow-up for #83: generated replies must declare phrase-level interrupt points, since a single end-of-speech point gives about 4.8 s at p50 to stop; this still bounds the paths that remain safe-point-bound (Interrupt by high-priority events, Yield for non-voice sources). Consequences noted by the author, not decided: ADR-0004's +SpeechCancelReason+ has no barge-in variant, so one is added in the implementation issue; ADR-0004 says lifecycle events carry digests and not text, so the heard prefix is stored as phrase index, offset and digest unless the retention-class question (ADR-0004 Q14) permits text; the stop is scheduler-executed, so the rank check still applies. Arithmetic, not simulated: confirmation at 464 / 528 ms (p50 / p90) plus 50 ms dispatch plus at most 150 ms fade gives a stop about 660 / 730 ms after onset, against 1410 / 2255 ms at phrase boundaries and 4832 / 7109 ms for today's single end-of-speech point.
. *S-4 (hold at next boundary)*: deferred to implementation; the reversible duck covers recovery now. Closes Q4.
. *S-5 (speculation and the lifecycle log)*: speculation stays out of the lifecycle log until commit, since the log is public truth. Speculative preparations and cancellations are counted in metrics only. Closes Q5.
. *S-6 (simulator)*: committed, consistent with #92, under link:../../examples/benchmarks/floor-sim/README.md[+examples/benchmarks/floor-sim/+]. It reads EXP-0001 outputs through +TURN_BENCH_DIR+, has a pinned requirements file and a README, contains no data and no machine paths, and CI does not run it. Closes the simulator half of Q6.
. *S-7 (microphone speaker)*: the normalizer assigns +source_class+ speech and +untrusted+ to any non-operator speaker. Even the operator's own microphone is content plane, never control. Floor priority comes from configuration, never from what was said. This is the rule. Closes Q7. It is consistent with S-3: a voice barge-in is untrusted content that can only make the performer stop, never publish or command.
. *#92 feedback*: the floor consumes raw activity edges without the 250 ms debounce (the D2 requirement is confirmed, closing the other half of Q6). The two 800 ms false-take numbers, 1% (causal raw activity) and EXP-0001's 4% (segment semantics), are both kept.

=== Implementation notes (#81 S2)

Recorded where the code departs from, or has to interpret, the text above. Operator documentation is in link:../production-runtime.adoc[production-runtime.adoc].

* *D6 feed liveness is a sidecar heartbeat, aged by receipt time.* The sidecar writes a bounded `{"vad":{"heartbeat":{"seq":N}}}` line only after processing audio; it is outside the `speech-observation` schema (it carries no observation, time or authority), and the app ages it by its own receipt time, not by a cross-process stamp. Until the first beat the rule is dormant (the S1 behaviour); the app enables the beat with the floor.
* *S-3 needed a stop primitive that did not exist.* The ADR assumed an audio stop path. `AudioOutput`/`AudioPlayer` had `play` only, and the production `ProcessAudioPlayer` detached its child, so even operator stop could not end audio already started. S2 adds `stop(fade_ms) -> AudioStopOutcome` (default `Unsupported`; the process backend hard-stops; the optional native backend fades). It is a method on the output the app already owns, called only from the app's barge-in path after the scheduler cancelled; it carries no authority. Operator stop was not changed (see the limits in production-runtime.adoc).
* *The stop follows the scheduler's arbitration.* A confirmed barge-in is conversation-priority untrusted input, so `Scheduler::stop_speaking_for` leaves a better-ranked performance and a non-interruptible one alone (recorded as `nothing_to_stop`); S-3's "stop at a non-safe point" applies to what the user speech could have preempted anyway. Reserved (queued) audio performances are cancelled with the playing one, since speaking over the user from a reservation would defeat the stop.
* *Execution requires a reported feed.* Stopping speech is the costly-to-reverse decision (D6), so the executor does nothing until the feed has reported liveness once. A sidecar without the beat therefore keeps the S1 behaviour (a confirmed yield is recorded, never executed).
* *Only confirmed yields are sequenced.* The executor evaluates the pure policy each tick and records a floor decision (with its sequence and logical time) only for a confirmed `Yield`, once per user speech run, so tentative and held evaluations at tick rate neither fill the bounded ring nor put speculation into the record.
* *Not implemented here.* A recovered feed counting its confirmation from the original raw start edge rather than from a fresh run (D6 last bullet): the S1 policy has no gap marker, and the sidecar's own `gap` already forces an end edge on a dropped audio chunk. The heard prefix (Q9), backchannels, early preparation and phrase-level interrupt points remain open.
* *Scene-aware floor (#83 S3b; closes the "#81 floor takes no scene input" note in ADR-0007 D-10).* Decision S-8: the floor takes the #88 S1 scene's interruptibility as a `TrustedInterruptibility`, never a bare `Interruptibility`, so a rank-4 perceived scene cannot reach a floor decision even by mistake; `unknown` (no context, stale or perceived) is the unchanged policy. An uninterruptible scene lengthens the take-turn silence to the top of its validated range and shortens the barge-in confirmation to half the configured run (floor 256 ms, the bottom of its range): the performer holds back and the human yields it sooner, with no new knob. Operator stop is not part of this path. Revisit when game-native telemetry (rank 1) or trusted timers (rank 3) exist, and when real conversation data replaces the synthetic thresholds (A-FLOOR-001).

== Consequences

=== Positive

* One threshold no longer carries every action: visible acknowledgement can occur at about 330 ms while the irreversible take stays at about 870 ms.
* Tentative interruption removes the cancel-on-any-sound failure without a pause primitive and without touching generation fencing.
* The policy is testable from synthetic fixtures before any microphone exists, and degrades to chat-only behaviour deterministically.
* Preparation waste and stale-feed hazards are bounded by construction and measured.

=== Costs / trade-offs

* Early preparation costs wasted LLM or TTS work (19 to 45 per 100 turn ends) for a lead of at most 192 to 480 ms.
* A freshness rule adds lag when the feed hiccups (p90 up by about 330 ms in the stalled trials).
* A confirm threshold adds about 160 to 320 ms of confirmation latency over a hard cancel.
* Non-verbal acknowledgement precedes almost every reply in this data; persona budgets are needed so it does not read as mechanical.
* Yield cannot be faster than safe-point density allows, and that is currently a single point per generated reply.

=== Known limitations

* *Synthetic data only.* Read sentences with three constructed pause lengths, no real hesitation, filler, overlap, breath, cough, backchannel, laughter or game audio, one language, one speaker per stream. The pause distribution makes "hold that survives 500 ms" and "colliding" nearly equivalent. EXP-0001 L1 to L14 apply.
* The barge-in false-yield test uses a surrogate (truncated VAD probability traces) and a noise class that produced almost no activations; it measures the machinery, not real coughs.
* No ASR or semantic evidence was available; the confirm rule is duration only. No human judged "acceptable" versus "annoying"; those words describe a mechanical overlap proxy.
* The executor (scheduler cooldowns, +min_reaction_spacing_ms+, the real avatar latency, audio start latency) is modelled by constants (duck 50 ms, dispatch 50 ms, backchannel 400 ms, reply 8 s). Ten phases per stream are correlated draws; Wilson intervals treat streams as independent.
* The causal numbers depend on treating sub-250 ms raw VAD runs as activity; the published EXP-0001 semantics give 4 percent at 800 ms where this gives 1 percent. Neither is a production rate.
* The simulator scripts are committed but its inputs are not: it needs the EXP-0001 saved scores, which are local only and must first be regenerated with the committed EXP-0001 scripts. After the path cleanup repro.py, run_table.py, run_stale.py, run_listen.py, run_bargein.py (first lines) and run_overlap.py were re-run against the original local files (same numbers); it was not re-run from an empty directory.
* External-project statements describe the files and commits named, not the projects in general. LiveKit's adaptive interruption detector and AIRI's VAD workers were not read.
* The Jev and persona paths are specified but not simulated.

== Staging and rollback

. Types, the pure policy and replay fixtures with no live input (no microphone); the text-chat-only mode first, behind configuration.
. Wire the #92 observation (VAD sidecar) in shadow mode: log decisions, act on none, compare with the fixed-800 baseline on recorded sessions.

Rollback at each stage is a configuration flag returning to the previous behaviour; the policy has no persistent state beyond the bounded decision ring.
