= Generative Fallback
:toc:

== Purpose

The generative path is the last resort after deterministic/cached reuse and the reflex/retrieval layer cannot satisfy an event. It runs outside the scheduler until a complete, validated Performance Asset exists.

The production-target implementation is split across:

* `crates/adapters::OpenAiResponsesAdapter` -- OpenAI-compatible Responses API ThinkingEngine.
* `crates/adapters::NormalizedHttpTtsAdapter` -- normalized HTTP TTS implementation.
* `crates/generative` -- routing audit, cancellation, fallback, streaming compilation state, and dynamic Performance Asset compilation.
* `crates/asset-store` -- validates generated provenance and accepts only completed compatible dynamic assets into the hot cache for later promotion.
* `crates/app` -- production composition: builds the curated ThinkingRequest, submits bounded provider work, revalidates completed output, inserts the completed generated asset, and reuses CachedPerformer/Scheduler for playback.

== Bounded non-blocking generation execution

`ProductionApp` never waits for remote Thinking/TTS completion on the composition thread. `GenerativeRuntime` owns one bounded provider worker with a bounded submission queue and a bounded completion mailbox. The default execution configuration permits one in-flight provider job and eight queued jobs; queue saturation does not spawn another thread or task.

Before submission, the composition thread selects the deterministic cached/non-verbal fallback and snapshots the side-effect-free public-output policy. The worker may perform provider waits and evaluate generated text before TTS, but it has no Scheduler, AssetStore mutation, authenticated control, or audit authority. Completed results return as immutable data and are committed only from `ProductionApp::tick()` after generation identity, cancellation, shutdown, and output-policy fencing pass.

If the submission queue is saturated, production immediately chooses the already-selected deterministic fallback and increments the saturation counter. `GenerationExecutionSnapshot` exposes pending/in-flight counts, the awaiting-drain count, high-water marks, saturation, completed, failed, cancelled/stale, queue capacity, shutdown state, and worker liveness without retaining per-request history.

Outstanding generation work is a three-state machine (queued, in-flight, awaiting drain), and both transitions claim the new state before releasing the old one: the worker claims in-flight before releasing pending, and claims the drain window before releasing in-flight. The composition thread releases the drain window when it takes the completion, so a job is always counted in at least one counter. Because that claim-before-release ordering spans separate atomics, the three state counters and the snapshot loads are sequentially consistent rather than relaxed; source ordering alone would not order writes to different atomics. `GenerationExecutionSnapshot::is_quiescent()` is therefore true only when nothing is queued, nothing is executing, and no completed result is published-but-undrained; callers that treat `pending == 0 && in_flight == 0` as "all generation work is accounted for" would otherwise observe a false idle state (issue #177).

For one event the buffered provider pipeline is:

. validate the source EventEnvelope and the bounded curated ThinkingRequest;
. verify the ThinkingRequest input provenance matches the source event;
. record the explicit LLM routing reason before the ThinkingEngine call;
. invoke the ThinkingEngine;
. check cancellation;
. evaluate generated text with the cloneable `PublicOutputPolicy` snapshot on the provider worker;
. reject/suppress text blocked by the narrow publication-containment policy or use the configured-secret-redacted text returned by that gate;
. invoke TTS only with gated public text;
. send TTS the speech projection of that text (ADR-0004 D-5: URLs, emoji and kaomoji deleted; the display text and the compiled asset keep the gated text; a reply with nothing left to speak takes the non-verbal fallback without a TTS call);
. check cancellation;
. compile a dynamic Performance Asset from the gated text and complete speech artifact;
. validate the asset;
. return the completed asset through the bounded completion mailbox;
. the composition thread revalidates publication policy and generation currency;
. production inserts it with `AssetStore::insert_hot` and schedules it through the existing `CachedPerformer` only after that commit fence.

The generative worker does not mutate Scheduler or AssetStore state while LLM/TTS work is in flight. A timeout, cancellation, malformed backend result, partial stream, late completion, or superseded result therefore cannot leave a half-scheduled performance behind.

Every attempted LLM invocation emits a production audit record containing the source event id, deterministic generation routing reason, and provider/model identity. Prompt text and generated reply text are deliberately excluded from this audit record, and configured secrets are redacted by the runtime audit boundary.

== Cancellation

`GenerationCancellationRegistry` associates the active generation with the same `aivtuber_scheduler::priority_for_event` mapping used by cached playback. A newly admitted higher-priority event cancels the active token before routing, and submitting a newer generation supersedes the previously active generation identity. Authenticated emergency stop/mute cancels the active generation without depending on model/network availability.

The pipeline checks cancellation before ThinkingEngine, after ThinkingEngine, after TTS, and immediately before returning a completed asset. The composition thread independently rejects any completion whose generation id/event id is no longer current, whose token is cancelled, or whose runtime is shutting down. Cancellation or partial streaming never inserts an asset or mutates the production scheduler.

Completion consumption finishes/removes the matching registry entry. Finishing a stale older completion cannot clear a newer active generation.

== Interaction deadline propagation

The composition root attaches the same end-to-end interaction deadline used by routing to submitted generation work. Before Thinking and again before TTS, the worker recomputes the remaining real execution time and caps the provider timeout to that remainder. Provider-specific maximum timeouts remain upper bounds; they never extend the interaction deadline.

If the remaining budget is below the configured minimum useful generation-start budget, the provider worker is skipped and the deterministic cached/non-verbal fallback is used. If provider work returns after the deadline, the composition-thread commit fence discards the completion even when the provider itself ignored cancellation or timeout. Generation telemetry records queue wait, provider execution, commit delay, the remaining budget, and typed deadline exhaustion without retaining generated text.

== Future-compatible speculative preparation invariant

The current production provider result remains buffered/atomic, but provider waits already run behind the bounded non-blocking execution boundary. A future implementation may additionally start speculative retrieval, Thinking, or TTS work before a turn/context is fully committed; that optimization MUST NOT weaken publication fencing.

Any future speculative path must:

* bind work to source event/revision plus generation/turn identity;
* treat provider output as disposable until the current context is revalidated;
* keep Scheduler mutation/public dispatch outside speculative work;
* run the deterministic publication-containment gate before irreversible publication;
* reject late/stale provider completion after cancellation or supersession;
* preserve #83-style atomic phrase/performance commit semantics when phrase streaming is enabled.

Remote-provider cancellation is best-effort. The local generation/revision fence is the authoritative stale-result defense.

Therefore "provider call completed" is never equivalent to "safe to publish".

== Phrase mode: atomic phrase commit (#83 S1)

Buffered mode commits one asset when the whole reply has been synthesized. For a long reply that makes the audience wait for the slowest stage, whole-reply TTS (measured at 2.3 s for a median 9.7 s reply on the local profile) and can exceed the TTS deadline outright. Phrase mode keeps every rule above and applies it to each phrase of the buffered Thinking reply instead; it is selected with `AIVTUBER_PHRASE_MODE=buffered|phrase|auto` (`auto` follows the composition profile; see <<phrase-default>>), and buffered mode stays available.

[source,text]
----
worker:       Thinking (buffered) -> whole-reply gate -> segment ->
              per phrase [ gate -> projection (+gate) -> TTS -> compile ] -> deliver
composition:  per phrase  currency + cancellation fence -> gate recheck -> scheduler commit
----

*Atomic phrase.* `PhraseUnit` (crates/generative, `phrase.rs`) carries the phrase sequence, the complete approved text, the compiled asset (complete audio reference, optional viseme/amplitude track, the interrupt point declared at the end of the phrase, Thinking and TTS provenance), the final flag and the response (generation/cancel) id. It can only be built by the pipeline for a phrase that reached `Compiled`. The state machine is `Planned -> Gated -> Synthesized -> Compiled -> Committed`; failure and cancellation are legal only before `Committed`, and `Committed` is terminal: a committed phrase is history.

*Segmentation* (`phrase-seg-v1`, `segment_reply`). Deterministic Japanese and English rules: sentence ends (`。！？` and ASCII `.!?` only when nothing word-like follows, so `3.14`, `example.com` and `?x=1` do not split; a short abbreviation list), line breaks, and clause breaks (`、` `,` `…`) that cut only past a clause weight. Trailing closers and emoji stay with their sentence. Lengths are weights (ASCII 1, other 2): a phrase is never cut below the minimum (a short tail merges back), a phrase past the preferred maximum is cut at the best earlier boundary (clause, then word space) and only a reply with no boundary at all is cut at the ceiling. The phrase count is bounded; a longer tail is merged into the last phrase. A phrase with nothing speakable (only a URL or emoji) joins its neighbour before delivery starts, so the final flag is fixed up front. The fixtures are `examples/phrase-segmentation/cases.json`. Reuse decision for the boundary primitive: `custom`; `unicode-segmentation` (UAX #29) was evaluated and not adopted because it supplies strong sentence breaks only and still needs these project rules, and it breaks before a trailing emoji or closing mark and after `Mr.`; revisit if a third language is needed.

*Lookahead.* Synthesis of phrase `n` starts only once phrase `n - 1` has started playing, so the synthesis of a phrase overlaps the playback of the one before it and never of older ones. The counter the worker waits on is written only by the composition thread; the wait is bounded (30 s) and ends with cancellation.

*Gate.* The whole reply is evaluated first, so a policy that refuses it decides while nothing is irreversible. With provider token streaming (`AIVTUBER_THINKING_STREAM`, docs/production-runtime.adoc) there is no whole reply before phrase 0, so a cumulative-prefix gate (committed display text plus the new phrase, bounded by the reply cap) stands in for it from phrase 1 on, and a whole-reply gate at completion is audit-only (docs/security-threat-model.adoc 11.2). Each phrase is then gated again on its own text (and its projection, with the display text through the gate last, as in buffered mode), and the composition thread re-applies the policy and requires the worker's decision to be for exactly that phrase immediately before its commit (docs/security-threat-model.adoc 11.2).

*Scheduler.* The existing shared scheduler executes the phrases. Phrase 0 is an ordinary reaction commit. Phrase `k > 0` is a continuation (`Scheduler::schedule_phrase_at`): it takes the derived event id `{event}#p{k}` (one live item per `event_id`, #198), starts exactly when the previous phrase ends (or at once when that already ended, without the reaction-spacing gap), and never preempts or displaces anything. When the previous phrase was cancelled or another item already holds the interval, the continuation is refused with `ContinuationBroken` and the reply ends. Every committed phrase declares an interrupt point at its end, which is what gives ADR-0005 barge-in and higher-priority preemption a safe boundary at every phrase instead of one at the end of the reply. Only phrase 0 starts the expression; later phrases keep it (cross-phrase continuity proper is #84).

*Failure and cancellation.* Failure before phrase 0 behaves exactly like buffered mode (the typed fallback directive: the pack's cached reaction when the group has an asset, speech-free in the starter pack; see <<visible-fallback>>). A gate refusal of phrase 0 at the commit boundary plays that same fallback; a refusal of any later phrase does not. Failure of phrase `k > 0` (TTS error or timeout, gate refusal, a refused commit) ends the reply after phrase `k - 1`: no retry, no replay of an earlier phrase, no fallback speech, and a typed counted cause (`PhraseCause`). The reply is recorded as `Partial`, never `Completed`, unless every planned phrase was committed. Operator stop or mute, a confirmed barge-in (including in the gap between two phrases), supersession by a newer generation and shutdown cancel the response, so no later phrase is committed; already committed phrases stop at the safe boundary or through the existing stop and fade path.

*Deadlines.* Phrase 0 is bounded by the interaction deadline like a buffered reply. Each phrase has its own synthesis budget (`AIVTUBER_PHRASE_TTS_TIMEOUT_MS`, default 12000), so a long reply no longer times out as a whole; later phrases are not bound by the interaction deadline because the audience is already hearing the reply.

*Replay and audit.* Every committed item carries a scheduler `PhraseLink` (response id, sequence, final flag) that the replay harness records and replays; items without one serialize exactly as before. `ProductionApp::recent_phrase_responses` keeps a bounded record per phrased reply: the segmentation version, the planned count, the commits in order (scheduler generation, logical commit time, start and end, gap before the phrase, gate outcome) and how the reply ended. The audit log gets `phrase_committed`, `phrase_refused` and `phrase_response_ended` records without text. `phrase_metrics` counts replies, completed and partial replies, committed phrases, gate refusals before the first and after a committed phrase, scheduler refusals, post-commit failures and cancellations, underruns and the largest inter-phrase gap, and TTS time.

[[phrase-default]]
*Default.* `auto` enables phrase mode for the `local` profile only, on the measured evidence in docs/local-profile-quickstart.adoc (whole-reply TTS is the dominant first-audio latency there, and the whole path is loopback). Every other profile stays buffered, the more conservative publication boundary for remote providers, until it has comparable evidence; `AIVTUBER_PHRASE_MODE=phrase` opts any profile in and `AIVTUBER_PHRASE_MODE=buffered` opts the local profile out. The mode is part of the composition fingerprint (`phrased_replies=true`), so replay and telemetry records name it; buffered composition keeps its existing fingerprint.

== Streaming compilation

`StreamingCompilationSession` is the provider-neutral path for streaming-capable LLM/TTS implementations.

Text may arrive in chunks. TTS progress may update a stable `audio_ref` with monotonically increasing duration. A Performance Asset cannot be finalized until a final speech chunk has been observed. Cancellation makes finalization fail. This keeps partial audio/text outside the scheduler while allowing a streaming provider to build the final artifact incrementally.

The current normalized HTTP TTS adapter is buffered; a provider with streaming transport can feed the same compilation session without changing asset or scheduler semantics.

== Graceful degradation

Backend failures are converted to typed `FallbackReason` values.

If `fallback_variant_group` has a compatible cached asset, the result is `CachedReaction` with a deterministic asset id and production routes it through the normal cached performer path. Otherwise the result is a `NonVerbalReaction` directive; the current production implementation performs no speech/publication for that directive. Thinking/TTS/output-gate failure never publishes a text-only or partial dynamic asset.

=== Visible fallback and the fallback counter (#288)

A silent reply is not an acceptable failure mode: a viewer who spoke sees nothing, and the operator sees nothing in the log. So the fallback is pack data, and it is counted.

* *Pack data.* When the route names no variant group the selection uses `reaction.neutral`; the `local` profile names it explicitly (`LOCAL_FALLBACK_VARIANT_GROUP`). The starter pack carries two speechless variants, `reaction.neutral.01` (`calm_soft` plus a nod) and `reaction.neutral.02` (`smile_soft` plus a nod), with no audio, so they play on the avatar alone and are chosen by the same deterministic seed as any cached variant. They use only presets the local renderer draws (`calm`, `joy`, `nod`; see `crates/adapters/src/local_avatar/presets.rs`); `thinking_*`, `tilt_head`, `recoil` and similar are not drawn there and must not be used for a visible fallback. A pack with no usable `reaction.neutral` still degrades to the typed `NonVerbalReaction` (nothing shown), and that case is counted as `unseen`.
* *Which failures.* Every generated reply that ends on a fallback: Thinking timeout, connection refused or any other transport failure, an invalid or empty provider answer, HTTP errors, a reply the output gate refuses (buffered mode and phrase 0), TTS failure, budget or capacity denial, and an expired deadline. The cached reaction goes through the ordinary cached performer path, so the scheduler, operator stop/mute and cancellation apply to it like any other reaction.
* *Counter and log.* `ProductionApp::generation_fallback_counts()` holds one counter per typed reason, using the existing closed vocabulary of `fallback_reason_name` (`timeout`, `unavailable`, `rate_limited`, `overloaded`, `authentication`, `invalid_request`, `policy_override`, `budget_exhausted`), plus `visible` and `unseen` totals. It is bounded by that vocabulary and stores no provider text. The daemon prints `generation_fallback: reason=<reason> count=<n> visible_total=<n> unseen_total=<n>` whenever a counter moves. The same reason is on the event's telemetry observation (`fallback_reason`). A refused connection, an invalid body and an HTTP 5xx all report `unavailable`: the vocabulary is the existing wire one and is not widened here.
* *Phrase mode.* A failure before phrase 0 takes this fallback (the worker returns the typed fallback exactly as buffered mode). A failure of phrase `k > 0` keeps the #83 behaviour: the reply ends after phrase `k - 1` with no fallback playback and no fallback count.

== Provenance and promotion

Generated assets set `provenance.generated=true` and store:

* generator identity;
* ThinkingEngine backend, model alias, and model version when available;
* TTS backend, model alias, and model version when available;
* the routing reason that caused the LLM call;
* the source event timestamp.

The Performance Asset JSON Schema and Rust runtime validator require the core provenance fields for generated assets. This allows a completed asset to be serialized, reviewed, and promoted into the asset store without losing the model/version/routing context that produced it.

== Configuration and secrets

API keys are passed only through adapter configuration and use redacted debug output. They are never embedded in the LLM/TTS request body, Performance Asset provenance, or public output.

The OpenAI-compatible adapter uses the Responses API shape and keeps endpoint/model selection configurable. The normalized TTS adapter likewise keeps endpoint, backend identity, model identity, voice model, and viseme mapping configurable.

Both HTTP provider adapters accept HTTPS endpoints or loopback-only HTTP endpoints, validated by the parsed URL authority rather than a string prefix. The exported shared HTTP transport repeats this validation at the network boundary so direct callers cannot bypass the endpoint policy and send secrets over remote plaintext HTTP. Loopback HTTP(S) requests bypass environment-configured HTTP proxies so local inference inputs and bearer keys are never routed through a proxy; remote HTTPS providers retain their configured proxy behavior. Redirects are not followed: a remote provider cannot use a 307/308 response to forward curated input to a different host, regardless of whether bearer authorization is stripped. The shared HTTP transport bounds decoded response bodies to 1 MiB (the underlying ureq default is 10 MiB), rejecting oversized responses rather than returning partial JSON. Redirects, malformed responses, and oversized responses fail through the existing typed backend/fallback path without publishing or caching partial output.

=== Thinking authentication policy (#220 S1)

The Thinking adapter takes a typed `ThinkingAuthentication`:

* `Bearer(key)` (default, `AIVTUBER_OPENAI_AUTH` unset or `bearer`) sends `Authorization: Bearer <key>`; a missing or blank key refuses to start.
* `UnauthenticatedLoopback` (`AIVTUBER_OPENAI_AUTH=unauthenticated-loopback`) carries no secret at all. It must be spelled out, must not be combined with `AIVTUBER_OPENAI_API_KEY` (the key would be silently ignored), and is accepted only when the endpoint host is IPv4 `127.0.0.0/8`, IPv6 `::1`, or exactly `localhost` resolved with every returned address loopback. Any other host name is refused even if it currently resolves to loopback; a non-loopback endpoint fails closed at construction, before any request.

There is no placeholder or dummy key anywhere: no domain/adapter state holds one and no `Authorization` header is built in unauthenticated mode (asserted by tests on the mock transport and on a real loopback socket). Deadlines, cancellation, error mapping, the plaintext-loopback proxy bypass, and the no-redirect rule are the same code path as the remote adapter. Residual risk: `localhost` is resolved at startup and again by the HTTP client at connect time; prefer `127.0.0.1` where a hostile hosts-file change is in scope.

The executable composition root creates the generative runtime only when explicitly enabled:

[source,text]
----
AIVTUBER_GENERATIVE_ENABLED=true
AIVTUBER_OPENAI_API_KEY=<secret>                # or AIVTUBER_OPENAI_AUTH=unauthenticated-loopback with a loopback endpoint
AIVTUBER_OPENAI_BACKEND_NAME=<optional-backend-name>
AIVTUBER_OPENAI_ENDPOINT=https://api.openai.com/v1/responses
AIVTUBER_OPENAI_MODEL=<model-alias>
AIVTUBER_OPENAI_MODEL_VERSION=<optional-version>
AIVTUBER_OPENAI_MAX_OUTPUT_TOKENS=256
AIVTUBER_OPENAI_TIMEOUT_MS=15000

AIVTUBER_TTS_ENDPOINT=http://127.0.0.1:PORT/...
AIVTUBER_TTS_BACKEND_NAME=normalized-http-tts
AIVTUBER_TTS_API_KEY=<optional-secret>
AIVTUBER_TTS_MODEL_ALIAS=<optional-alias>
AIVTUBER_TTS_MODEL_VERSION=<optional-version>
AIVTUBER_TTS_TIMEOUT_MS=15000
----

Voice model, viseme mapping, compiler version, avatar profile, and motion library are inherited from the same runtime compatibility configuration used by `AssetStore`, so a generated asset cannot be inserted when its compiler/TTS compatibility disagrees with production playback.

=== Thinking wire and the OpenRouter preset (#363)

`OpenAiResponsesAdapter` speaks one of two request/response shapes, chosen by `ThinkingWire`; the default stays `responses`, byte-identical to before. The chat-completions wire exists so the same adapter, with the same authentication, timeout, streaming and fallback machinery, can talk to OpenRouter and other OpenAI-compatible chat servers. There is no second client.

[cols="2,3"]
|===
|Variable |Effect

|`AIVTUBER_OPENAI_WIRE`
|`responses` (default) or `chat-completions`. Chat sends `{model, messages:[{role:"user", content}], max_tokens[, stream]}` and reads `choices[0].message.content` (streaming reads `choices[0].delta.content`). Anything else is a startup error.

|`AIVTUBER_THINKING_PROVIDER`
|Unset or `generic`: no preset. `openrouter`: sets the endpoint to `https://openrouter.ai/api/v1/chat/completions`, the wire to `chat-completions`, the attribution headers and the data-collection default below. Any other value is a startup error. `AIVTUBER_OPENAI_MODEL` must also be set (an OpenRouter id such as `vendor/model`); the built-in default model name is not one. The bearer key is still `AIVTUBER_OPENAI_API_KEY`.

|`AIVTUBER_OPENROUTER_REFERER`
|`HTTP-Referer` value; sent only when set (there is no default, so no project URL goes to OpenRouter unasked). Needs `AIVTUBER_THINKING_PROVIDER=openrouter`.

|`AIVTUBER_OPENROUTER_TITLE`
|`X-Title` value; default `aivtuber`. Needs the openrouter preset.

|`AIVTUBER_OPENROUTER_DATA_COLLECTION`
|`deny` (default with the preset) or `allow`. Sent as `provider: {"data_collection": ...}` so viewer chat is not retained for training. Only the openrouter preset sends a `provider` field; the generic chat wire never does. `allow` must be spelled out.
|===

Explicit `AIVTUBER_OPENAI_ENDPOINT`, `AIVTUBER_OPENAI_MODEL` and `AIVTUBER_OPENAI_WIRE` win over the preset; a variable that would be silently ignored (an `AIVTUBER_OPENROUTER_*` value without the preset, or with the `responses` wire) is a startup error instead. Startup prints ` wire=<wire> data_collection=<policy>` after the usual `thinking:` line only when the wire is not `responses`. The preset works under the `full` profile; a dedicated profile is separate work (#364).

Boundaries:

* *Extra headers* are a typed, bounded `ExtraHeaders` (at most 4; ASCII token names; printable-ASCII values, so no CR/LF; no duplicates; never `content-type`, `accept`, `authorization`, `host`, `cookie` and similar transport-owned names). Validation happens at construction, `Debug` prints names only, and a transport that does not support headers refuses a non-empty set instead of dropping it. Existing callers send none.
* *HTTP 402* (credits exhausted) maps to `EngineErrorKind::QuotaExhausted`. It degrades to the deterministic fallback like every other kind and is reported with the existing wire reason `unavailable`, because the `FallbackReason` vocabulary is a closed wire schema that this change does not widen. The typed kind stays visible in the warm-up log and conformance output as `quota_exhausted`. An `{"error":{"code":N}}` body inside HTTP 200 keeps the status it names. 401/403 are `authentication`, 429 `rate_limited`, 503/529 `overloaded`, other 5xx `unavailable`.
* *Usage* (`usage.prompt_tokens`, `completion_tokens`, `cost`) is parsed into a bounded `ThinkingUsage` on `GeneratedReply.usage`: token counts saturate at `u32::MAX`, cost is integer micro-USD, and a missing, malformed, negative, non-finite or implausibly large value becomes absent, never an error. Streaming takes usage from the final chunk (OpenRouter sends it with an empty `choices`). It is audit data only; nothing in this change reads it for routing, telemetry or display (see #367).
* The API key is never in a request body, header set, `Debug` output or error message.

== Verification

The Rust tests cover:

* routing-reason recording for successful and failed LLM calls;
* higher-priority cancellation;
* cancellation before LLM, after LLM, and after TTS;
* unchanged scheduler state after cancelled partial generation;
* cached and non-verbal fallback after TTS failure;
* deterministic generated asset identity;
* full thinking/TTS model provenance;
* promotion into `AssetStore`;
* streaming final-chunk gating and cancellation;
* production generate -> publication-containment gate -> TTS -> hot insert -> shared scheduler playback;
* production output redaction and suppression before TTS;
* production thinking timeout/TTS failure -> cached or non-verbal fallback;
* production high-priority and authenticated emergency cancellation;
* serialized control events cannot cancel generation through content ingress;
* partial streaming output never inserts/schedules a generated asset;
* secret redaction and HTTP wire mapping in provider adapters.
