= Generative Fallback
:toc:

== Purpose

The generative path is the last resort after deterministic/cached reuse and the reflex/retrieval layer cannot satisfy an event. It runs outside the scheduler until a complete, validated Performance Asset exists.

The production-target implementation is split across:

* `crates/adapters::OpenAiResponsesAdapter` -- OpenAI-compatible Responses API ThinkingEngine.
* `crates/adapters::NormalizedHttpTtsAdapter` -- normalized HTTP TTS implementation.
* `crates/generative` -- routing audit, cancellation, fallback, streaming compilation state, and dynamic Performance Asset compilation.
* `crates/asset-store` -- validates generated provenance and can accept completed dynamic assets into the hot cache for later promotion.

== Atomic generation pipeline

For one event the buffered path is:

. validate the curated ReflexRequest;
. record the explicit LLM routing reason before the ThinkingEngine call;
. invoke the ThinkingEngine;
. check cancellation;
. invoke TTS;
. check cancellation;
. compile a dynamic Performance Asset;
. validate the asset;
. return the completed asset to the caller.

The generative crate does not mutate Scheduler state while LLM/TTS work is in flight. A timeout, cancellation, malformed backend result, or partial stream therefore cannot leave a half-scheduled performance behind.

== Cancellation

`GenerationCancellationRegistry` associates the active generation with the event priority used by the scheduler. A newly arrived event cancels the active token only when the new event has strictly higher priority.

The pipeline checks cancellation before ThinkingEngine, after ThinkingEngine, after TTS, and immediately before publish.

Callers should finish/remove the registry entry after the generation result has been consumed.

== Streaming compilation

`StreamingCompilationSession` is the provider-neutral path for streaming-capable LLM/TTS implementations.

Text may arrive in chunks. TTS progress may update a stable `audio_ref` with monotonically increasing duration. A Performance Asset cannot be finalized until a final speech chunk has been observed. Cancellation makes finalization fail. This keeps partial audio/text outside the scheduler while allowing a streaming provider to build the final artifact incrementally.

The current normalized HTTP TTS adapter is buffered; a provider with streaming transport can feed the same compilation session without changing asset or scheduler semantics.

== Graceful degradation

Backend failures are converted to typed `FallbackReason` values.

If `fallback_variant_group` has a compatible cached asset, the result is `CachedReaction` with a deterministic asset id. Otherwise the result is a `NonVerbalReaction` directive. TTS failure never publishes a text-only partial dynamic asset.

== Provenance and promotion

Generated assets set `provenance.generated=true` and store:

* generator identity;
* ThinkingEngine backend, model alias, and model version when available;
* TTS backend, model alias, and model version when available;
* the routing reason that caused the LLM call;
* the source event timestamp.

The Performance Asset JSON Schema and Rust runtime validator require the core provenance fields for generated assets. This allows a completed asset to be serialized, reviewed, and promoted into the asset store without losing the model/version/routing context that produced it.

== Configuration and secrets

API keys are passed only through adapter configuration and use redacted debug output. They are never embedded in the LLM/TTS request body, Performance Asset provenance, or public output.

The OpenAI-compatible adapter uses the Responses API shape and keeps endpoint/model selection configurable. The normalized TTS adapter likewise keeps endpoint, backend identity, model identity, voice model, and viseme mapping configurable.

== Verification

The Rust tests cover:

* routing-reason recording for successful and failed LLM calls;
* higher-priority cancellation;
* cancellation before LLM, after LLM, and after TTS;
* unchanged scheduler state after cancelled partial generation;
* cached and non-verbal fallback after TTS failure;
* deterministic generated asset identity;
* full thinking/TTS model provenance;
* promotion into `AssetStore`;
* streaming final-chunk gating and cancellation;
* secret redaction and HTTP wire mapping in provider adapters.
