== #35 implementation target

#35 should make Rust and repository JSON Schema accept/reject the same versioned wire documents.

Known drift called out by the issue:

* Event Envelope JSON Schema rejects unknown fields while Rust currently does not fully enforce closed-object deserialization.
* JSON Schema validates `observed_at` as `date-time`; Rust currently treats it as an unchecked string.
* ReflexDecision and other versioned wire structs require an equivalent parity audit.

Expected work:

* strict Rust deserialization where schemas use `additionalProperties: false`
* consistent timestamp validation
* representative positive fixture for every EventKind
* negative fixtures for unknown fields, timestamps, trust/source/plane mismatches, probabilities, versions
* Rust -> JSON -> JSON Schema CI parity
* schema-valid fixture -> Rust deserialize + validate parity
* documented schema evolution/change-order rules

This should land before #9 is considered production-wire stable.

== Safety and architecture invariants to preserve

Do not regress these established rules:

* Rust `crates/` is the production target; TypeScript `src/` is reference/prototype unless an issue explicitly says otherwise.
* serialized authorization claims are not authenticated authority.
* control/emergency paths bypass content backpressure and model availability.
* scheduler logical time is deterministic and external adapter failure does not own scheduler state.
* reconnect must not replay stale scheduled actions.
* binary/generated media remains external to Git; descriptors/metadata may be versioned.
* LLM output is data, never capability-bearing control.
* generated partial output must not mutate scheduler state.
* every external-model call/fallback must retain typed reason/provenance needed for replay and telemetry.
* avoid adding network I/O to scheduler/frame-loop hot paths.
