= Roadmap
:toc:

== Phase 0 -- Architecture baseline

* Define domain events and state snapshots.
* Define DecisionEngine boundary.
* Define Performance Asset schema.
* Define telemetry and replay requirements.
* Establish Rust workspace and CI.

== Phase 1 -- Deterministic performer

* Event bus.
* Performance scheduler.
* In-memory asset store.
* Mock audio/avatar adapters.
* Deterministic fillers/reactions.
* Replay harness.

Exit criterion: a recorded event trace deterministically produces the same performance plan.

== Phase 2 -- Real avatar/audio integration

* VTube Studio adapter.
* OBS WebSocket adapter.
* audio playback abstraction.
* pre-generated filler/reaction asset pack.
* viseme timeline support.

Exit criterion: cached reaction path works end-to-end without LLM/TTS.

The Rust production composition for this exit criterion lives in +crates/app+: content ingress, compatibility-checked cached asset resolution, the deterministic scheduler, process audio playback, and VTube Studio output share one lifecycle. Local live smoke still requires materialized audio files and a configured VTube Studio model; see link:production-runtime.adoc[Production Rust composition runtime].

== Phase 3 -- Jev reflex layer

* Jev adapter.
* batched routing decisions.
* strict timeout/fallback behavior.
* semantic retrieval + Jev reuse gate.
* decision telemetry.

The Rust semantic path builds deterministic indices from compatibility-checked AssetStore entries with precomputed versioned embeddings. Replay records the embedding/index/compiler metadata and selected asset identity; stale identity is rejected before playback.

Exit criterion: comparative replay reports whether Jev changes LLM routing, cost, and latency while preserving operator-reviewed reaction quality. Benefit is not assumed without measurements from an identified dataset/configuration.

== Phase 4 -- Generative fallback

* OpenAI-compatible LLM adapter.
* TTS adapter(s).
* streaming text/audio path.
* dynamic Performance Asset compilation.
* promotion policy.

Status: implemented on the Rust production path. Generated assets are published atomically only after complete LLM/TTS output, with priority cancellation, cached/non-verbal degradation, streaming compilation state, and replayable provenance. Promotion policy decisions beyond making assets promotable remain an offline/adaptation concern.

== Phase 5 -- Memory and adaptation

* working-memory compaction.
* viewer/topic relevance.
* frequency-based asset promotion.
* bounded variation and anti-repetition.
* offline threshold calibration.

Status: implemented on the Rust production path. Working memory is byte/time/count bounded and stores pseudonymous viewer metadata; durable retention requires a `SecurityRuntime` memory-write permit. Generated-asset promotion/invalidation uses explicit deterministic frequency/quality policy, preserves provenance/runtime compatibility, and emits replayable decision records. Threshold inputs come from the Phase 6/#10 calibration dataset rather than live self-tuning. See link:memory-adaptation.adoc[Memory and Adaptation Runtime].

== Phase 6 -- Benchmark and hardening

* replay benchmark suite.
* failure injection.
* long-stream soak tests.
* cost/latency dashboards.
* privacy retention policies.

Status: the Rust production path records bounded event observations and the checked-in replay runner compares deterministic, semantic, semantic+Jev, and full-generative modes on one fixture boundary with reproducibility metadata and calibration export. `crates/hardening` adds deterministic cross-subsystem fault injection, content-flood/emergency-control verification, and an eight-logical-hour soak report using the same telemetry summary vocabulary. The soak intentionally reports remaining lifetime-growth findings tracked by #50-#53 rather than masking them. See link:failure-soak.adoc[Failure Injection and Long-Stream Soak].
