= Failure Injection and Long-Stream Soak
:toc:

== Purpose

Issue #40 adds deterministic reliability tooling around the Rust production path. The goal is to make degraded behavior replayable and measurable without putting fault-only logic into production crates.

The harness lives in +crates/hardening+.

== Deterministic fault plans

+FaultPlan+ is an ordered set of one-based subsystem call occurrences and typed fault kinds. The same plan and seed always inject the same fault at the same boundary.

Supported subsystem boundaries are:

* Jev/System One;
* Thinking/LLM;
* TTS;
* VTube Studio;
* OBS;
* audio playback;
* Performance Asset storage;
* semantic index construction/search;
* content ingress.

The integration tests under +crates/hardening/tests/external_faults.rs+ connect the plan to real provider-neutral adapter injection points:

* Jev +HttpTransport+;
* OpenAI-compatible/TTS +JsonHttpTransport+;
* VTS/OBS +WebSocketConnector+;
* process audio availability;
* real Performance Asset validation;
* real semantic-index validation.

Timeout, unavailable, rate-limit, disconnect, corrupt, incompatible, and flood cases therefore remain typed at the same boundaries used by production.

== Control-plane invariants

+run_content_flood+ fills the configured content queue until +DroppedBackpressure+ is observed, then exercises authenticated stop and mute through +LocalControlIngress+ while the queue is still saturated.

The stop must cancel active scheduler work and mute must succeed without draining or waiting behind content.

Existing production tests continue to cover complementary degraded-mode invariants:

* active generation is cancelled by authenticated emergency control;
* serialized control claims cannot mint control authority;
* avatar reconnect does not replay a failed due command;
* VTS and OBS adapter reconnect tests do not replay stale actions;
* LLM/TTS timeout and unavailable failures fall back without publishing partial generated assets.

== Logical-time soak workload

+SoakConfig::default()+ models eight logical stream hours at 20 content events/second:

----
576000 events
50 ms logical event interval
128 content queue capacity
256 working-memory entry capacity
1 generated asset every 200 events
10% scheduler cancellation cycles
----

The workload runs without wall-clock sleeping. This keeps CI/replay deterministic while exercising the state transitions that accumulate over a long stream.

The CI smoke uses 5,000 events. A full local report uses the default eight-hour logical workload:

[source,shell]
----
cargo run --locked -p aivtuber-hardening --bin failure-soak -- target/hardening-soak.json
----

A smaller explicit run is:

[source,shell]
----
cargo run --locked -p aivtuber-hardening --bin failure-soak -- target/hardening-smoke.json 5000
----

== Growth detection

The soak records midpoint and final retained-state counts for:

* scheduler total items and live items;
* SecurityRuntime content queue;
* in-memory security audit records;
* bounded working memory;
* detailed telemetry events;
* hot Performance Assets.

A metric is marked +lifetime_growth_detected+ when the second half continues materially increasing with cumulative event count. Configured live-state bounds are separately marked +configured_limit_exceeded+ and make the CLI fail.

Known lifetime-growth findings are intentionally reported, not hidden:

[cols="1,1,2"]
|===
|Metric |Issue |Meaning

|raw stdin pre-runtime buffering
|#50
|Covered by the content-flood family but fixed separately because it occurs before +SecurityRuntime+.

|audit / telemetry retained detail
|#51
|Common production retention policy is still required.

|scheduler terminal history
|#52
|Live scheduler state reaches zero, while completed/cancelled history continues growing.

|generated hot assets
|#53
|Generated L0 residency currently grows with unique generated asset count.
|===

#40 owns reliable detection and reproduction of these conditions. It does not silently fold the retention-policy fixes into the failure harness.

== Reproducibility and #10 telemetry

Every JSON report contains the same +ReproducibilityMetadata+ family introduced by #10:

* dataset id;
* git revision and dirty marker;
* Rust/Bun toolchain versions;
* hardening config version;
* asset version;
* seed;
* represented stream duration.

The report also includes a +BenchmarkSummary+ generated by +TelemetryCollector::summary+, so routing/fallback/cancellation observations use the same aggregate vocabulary as the #10 comparison reports without cloning the complete event-detail set.

== CI

The required Rust CI job runs:

[source,shell]
----
cargo test --locked --workspace
cargo run --locked -p aivtuber-hardening --bin failure-soak -- target/ci-hardening-soak.json 5000
----

The smoke fails if a configured live-state bound is exceeded or authenticated stop/mute stops working under content flood. Lifetime-growth findings tied to explicit retention issues remain visible in the JSON report and console output.
