= Provider-Neutral Domain Contract
:toc:
:toclevels: 3

== 1. Purpose

This document defines the stable data contract shared by event ingestion, deterministic scheduling, reflex decisions, replay, and future provider adapters.

Provider-specific wire types MUST remain outside this contract.

== 2. Event envelope

Every external or internal stimulus is normalized into an `EventEnvelope`.

Required concepts:

* schema version
* globally unique event id
* correlation id
* source
* typed source class
* security plane
* trust level
* event kind
* monotonic sequence number
* observed wall-clock timestamp
* normalized payload
* optional pseudonymous actor id
* optional upstream priority hint

The wall-clock timestamp is for observability. Ordering and replay MUST use the monotonic sequence/timeline, not wall-clock time.

== 3. Event kinds

Initial normalized event kinds:

* `chat.message`
* `chat.donation`
* `speech.input`
* `game.event`
* `stream.event`
* `timer.tick`
* `operator.command`
* `system.health`

Provider-specific subtypes belong inside payload metadata rather than creating provider-specific domain enums.

=== 3.1 Source class and trust invariants

The normalizer, not the incoming payload, assigns `source_class`, `plane`, and `trust_level`.

Only `operator.command` may carry an `authorization` object. A public content adapter cannot mint a trusted operator event merely because its payload contains command-like text. The serialized `AuthorizationContext` is an audit/replay claim, not authenticated runtime authority; privileged Rust actions require the non-serializable `AuthenticatedControl` minted by the local ingress path.

Security rationale and capability rules are defined in `security-threat-model.adoc`.

== 4. Typed reflex and thinking context

Routine reflex decisions receive a versioned `ReflexRequest`, not an arbitrary JSON state map and not an unbounded transcript.

`ReflexRequest` contains:

* the normalized current `EventEnvelope`;
* a versioned `ReflexContext`;
* a bounded `RetrievalSnapshot`.

`ReflexContext` contains explicit provider-neutral snapshots:

* `PerformerSnapshot`: speaking state, current asset/interruptibility, bounded mood/arousal values;
* `StreamSnapshot`: bounded mode/topic labels;
* `RecentInteractionSnapshot`: bounded recent reaction families, asset ids, and time since direct reply;
* optional monotonic `now_ms`.

`RetrievalSnapshot` contains at most eight ordered candidates. Each candidate records `asset_id`, one-based `rank`, and normalized similarity. Candidate ids and ranks must be unique and ranks must be contiguous from one.

All snapshot strings and lists have fixed production bounds in `crates/domain/src/context.rs`. The Jev adapter serializes only these explicit fields plus the current normalized event and applies its own compact-state byte cap before transport.

=== 4.1 ThinkingRequest

`ThinkingEngine` accepts a dedicated versioned `ThinkingRequest`; it does not reuse `ReflexRequest`.

A thinking request contains only:

* one explicitly curated current-event `ThinkingContent`;
* typed performer/stream/recent/retrieval snapshots;
* a bounded list of explicitly curated context items.

Every `ThinkingContent` item carries its source class, trust level, privacy class, optional event provenance, and bounded text. Untrusted viewer content therefore remains marked `untrusted` when it crosses the thinking boundary; constructing the request does not elevate trust.

A `memory` context item additionally carries `epistemic_class` — the class its claim was retained under (`verified_fact`, `viewer_claim`, `performer_experience`, `observation`, `persona_opinion`). The field is present exactly on `memory` items: a memory item without it, or a non-memory item that carries one, is rejected by `ThinkingRequest::validate`, so provenance can neither be dropped in transit nor invented for content that was never retained. Carrying a class is a phrasing input, not an authorization: it is not a capability and cannot widen what the runtime will emit.

Raw transcript or stream-history fields are not part of either request type. If historical content is needed for generation, an upstream component must deliberately reduce/select it into bounded `curated_context` items with explicit provenance, trust, and privacy metadata.

The initial internal request schema versions are `ReflexRequest 0.1.0`, `ReflexContext 0.1.0`, and `ThinkingRequest 0.1.0`. Reflex replay records carry both the request and context schema versions.

=== 4.2 Perception observations

Optional perception (issue #90, ADR-0007) reaches the runtime only as a `PerceptionObservationBatch`, specified by `schemas/perception-observation.schema.json` (version `0.1.0`) and `crates/domain/src/perception.rs`. It is a separate observation batch like the speech observation (ADR-0007 D-Q1): it is not an `EventEnvelope` event and has no `SourceClass`.

* *Wire form.* An envelope (`schema_version`, `provider_id`, `provider_version`, one `observations` array of at most 8, batch capped at 16 KiB before parsing) of tagged observations (`screen_scene`, `screen_caption`). Each carries `observation_id`, `source.alias` (an operator label, never a window title or path), `frame` identity (`capture_seq`, `captured_at_ms`, downscaled `width`/`height`, no pixels or hash), `observed_at_ms` and a *required* `expires_at_ms` (after `observed_at_ms`, at most 30 s later), optional `confidence` with `calibrated`, a `producer` identity (`model_id`, `config_digest`, `prompt_version`), a `privacy` class, `redaction` counters, and a kind-fixed `payload`: a closed provisional `scene_class` with at most 8 closed-vocabulary `labels`, or one `caption` of at most 240 UTF-8 bytes with no control, bidi, zero-width or NFKC-unstable characters.
* *No self-escalation.* There is no trust, plane, source class, priority, authorization or capability field. Every object rejects unknown fields, so an observation that asserts any of them, or carries an image, bounding box, embedding or free-form map, is invalid.
* *Ingress assigns.* `aivtuber_runtime::PerceptionTracker` assigns plane `content` and trust `untrusted` to everything (`PerceptionProvenance`), raises privacy to the operator's per-source floor (never lowers it), drops and counts labels outside the operator vocabulary, redacts secrets from captions, and rejects by counted reason: `disabled`, `future_dated`, `stale_age`, `expired`, `out_of_order`, `redaction_failed` (batch-level: `oversize`, `invalid`, `disabled`). Ordering is by `capture_seq` and observed time on the runtime's monotonic or logical clock, never by arrival.
* *Off by default.* A source is enabled only by an authenticated operator capability (`AuthenticatedControl` holding `obs.control`) for an alias in the operator's allowlist; while nothing is enabled, bytes are refused before parsing. Disabling drops that source's retained state at once.
* *Source hierarchy.* Per field, a higher-ranked fresh source (trusted telemetry, known OBS state, trusted timers) always wins; perception fills a field only when those are silent; a disagreement is counted, never blended (`resolve_scene`).
* *Consumers.* Reflex and Jev may be handed only `PerceptionSceneSnapshot` (closed scene class and closed-vocabulary labels; no free-text field exists on it). Thinking may receive at most one `ThinkingContent` item with `source: screen_observation`, `trust_level: untrusted`, no event identity, at most 512 UTF-8 bytes including delimiters and an age, validated by `ThinkingRequest::validate`. Perceived text never reaches memory, TTS or Reflex and is never parsed for control or performance information.
* *Replay.* `examples/perception-observations/replay/*.json` run through `PerceptionReplayFixture` with logical time and no OBS or model; the observation, not the model, is the replay input.

== 5. Normalized reflex decision

The provider-neutral output contains both selected values and uncertainty.

Minimum fields:

* chosen response route
* route confidence, when available
* reaction family
* gesture family
* attention target
* interrupt probability
* cache-reuse probability
* normalized importance in 0..1
* normalized emotion intensity in 0..1
* backend identity
* backend model alias/version when available
* decision latency
* fallback reason, if fallback occurred

The domain contract must not expose Jev's wire DTOs or another provider's schema.

== 6. Response route

Allowed initial routes:

* `silent`
* `reaction`
* `cached`
* `template`
* `llm`

A provider may recommend a route, but deterministic policy is authoritative.

== 7. Fallback reasons

Normalize failures so scheduler/replay logic does not depend on provider-specific errors.

Initial reasons:

* `none`
* `timeout`
* `unavailable`
* `rate_limited`
* `overloaded`
* `authentication`
* `invalid_request`
* `low_confidence`
* `policy_override`
* `operator_override`

== 8. Performance plan

A compiled `PerformancePlan` references immutable or versioned assets and a shared monotonic timeline.

Conceptual fields:

* plan id
* source event id(s)
* priority
* asset ids
* start policy
* safe interrupt points
* cancellation token/generation id
* seeded variation value
* fallback action

The scheduler owns execution. The decision engine does not directly execute avatar parameters.

== 9. Replay contract

Every decision-affecting input must be recordable:

* normalized event
* compact typed state snapshot
* exact ReflexRequest/ReflexContext schema versions
* retrieval candidates with compatibility-stable asset identity, rank, and similarity
* retriever/embedding-model/index-snapshot/asset-compiler versions
* decision output
* deterministic threshold/config version
* executed action
* random seed
* operator override
* latency/cost metadata

Given the same trace, config, assets, and seed, deterministic scheduling SHOULD reproduce the same planned actions.

External model calls may be replayed from recorded outputs rather than reissued.

== 10. Versioning

Domain JSON documents carry `schema_version`.

The repository JSON Schemas under +schemas/+ are the normative wire-format source of truth. Rust production-domain types and validators must accept and reject the same versioned documents; TypeScript/reference code must follow the same schemas rather than defining a second wire contract.

Change procedure:

. Change the relevant JSON Schema and positive/negative fixtures first.
. In the same pull request, update the Rust type/validator and any reference implementation.
. Run both directions of parity: repository fixtures -> Rust deserialize/validate, and Rust serialize -> repository JSON Schema.
. Update replay fixtures and documentation with the exact schema version.

Version rules:

* additive optional fields may remain on the current version when old readers can safely ignore them and the schema remains backward compatible;
* any incompatible wire change requires a +schema_version+ change, including adding a required field, removing/renaming a field, changing a field type, narrowing an accepted value set, or changing enum/security semantics;
* validator fixes that only make an implementation enforce constraints already present in the current normative schema do not by themselves require a version bump;
* replay fixtures record the exact schema/config versions;
* adapters must reject unsupported versions rather than guessing or coercing them.

== 11. Privacy boundary

Durable traces SHOULD avoid raw platform identifiers when a pseudonymous actor id is sufficient.

Production actor pseudonyms use a keyed cryptographic construction outside the serialized domain contract. The deployment key is not Event Envelope/replay/model state; source/provider namespace is part of the pseudonymization domain so identical raw actor strings from different providers do not become the same durable identifier.

Retention of raw chat/STT text must be configurable separately from normalized replay metadata.

== 12. Machine-readable schemas

* `schemas/event-envelope.schema.json`
* `schemas/reflex-decision.schema.json`
* `schemas/perception-observation.schema.json` (section 4.2)

CI validates repository fixtures with the schemas, then deserializes/validates the same fixtures through the Rust production-domain types. It also serializes Rust values for every Event kind plus representative Reflex Decisions and validates those JSON documents against the repository schemas.

The Event Envelope schema is currently version `0.2.0`; this version introduces required trust-boundary fields and is intentionally incompatible with the earlier `0.1.0` envelope. The normalized Reflex Decision schema remains `0.1.0`.
